پروکسی سیستمی و حالت TUN فقط تا وقتی کار می‌کنند که یک نمایه در حال اجرا باشد. در این حالت Throne روی پورت mixed هم گوش می‌دهد که به‌طور پیش‌فرض `127.0.0.1:2080` است و اتصال‌های پروکسی SOCKS و HTTP را می‌پذیرد.

وقتی هیچ نمایه‌ای در حال اجرا نیست، یا وقتی برنامه‌ای پروکسی سیستمی را دور می‌زند، ترافیک آن از اتصال معمول شما استفاده می‌کند. برای اینکه به‌جای آن چنین ترافیکی مسدود شود، [کیل‌سوییچ](@/advanced/kill_switch.fa.md) را روشن کنید.

## پروکسی سیستمی {#system-proxy}

در پنجرهٔ اصلی تیک `پروکسی سیستمی` (System Proxy) را بزنید، یا در منوی سینی سیستم (tray) از `Operation Mode` ← `پروکسی سیستمی` (System Proxy) استفاده کنید. تا وقتی یک نمایه در حال اجراست، Throne تنظیم پروکسی سیستم شما را روی پورت mixed می‌گذارد. به دسترسی مدیر (administrator) نیازی نیست.

فقط برنامه‌هایی از آن استفاده می‌کنند که از تنظیم پروکسی سیستم پیروی می‌کنند، مانند بیشتر مرورگرها. برنامه‌های دیگر مستقیم وصل می‌شوند، برای نمونه Discord، تماس‌های Telegram، ترمینال‌ها، برنامه‌های Microsoft Store (UWP) و بسیاری از بازی‌ها.

- **Windows:** Throne تنظیم پروکسی Windows را با `قالب پروکسی` (Proxy Format) در [تنظیمات ورودی](#inbound-settings) می‌نویسد.
- **Linux:** فقط GNOME و KDE پشتیبانی می‌شوند. Throne را با کاربر عادی خود اجرا کنید، نه با root؛ وگرنه نمی‌تواند این تنظیم را تغییر دهد.
- **macOS:** Throne پروکسی HTTP، HTTPS و SOCKS را برای همهٔ سرویس‌های شبکهٔ فعال تنظیم می‌کند.

بسیاری از ابزارهای خط فرمان پروکسی سیستم را نادیده می‌گیرند، اما `HTTP_PROXY` و `HTTPS_PROXY` را می‌خوانند:

```bash
export HTTP_PROXY=http://127.0.0.1:2080 HTTPS_PROXY=http://127.0.0.1:2080
```

```powershell
$env:HTTP_PROXY = "http://127.0.0.1:2080"; $env:HTTPS_PROXY = "http://127.0.0.1:2080"
```

- اگر Throne در حالی که نمایه‌ای در حال اجراست به‌اجبار بسته شود یا از کار بیفتد، این تنظیم باقی می‌ماند و برنامه‌های شما نمی‌توانند وصل شوند. [پرسش‌های متداول](@/help/faq.fa.md#force-quit) را ببینید.
- تا وقتی تیک `پروکسی سیستمی` (System Proxy) زده شده است، درخواست‌های خود Throne، مانند به‌روزرسانی اشتراک‌ها، هم از طریق پورت mixed فرستاده می‌شوند.

## حالت TUN {#tun-mode}

در پنجرهٔ اصلی تیک `حالتvpn` (Tun Mode) را بزنید، یا در منوی سینی سیستم از `Operation Mode` ← `حالتvpn` (Tun Mode) استفاده کنید. سپس Throne ترافیک کل رایانه، از جمله DNS، را از یک آداپتور شبکهٔ مجازی عبور می‌دهد. این کار به دسترسی مدیر یا root نیاز دارد؛ [حالت TUN](@/guides/tun_mode.fa.md) را ببینید.

## از کدام حالت استفاده کنیم {#which-mode}

| | پروکسی سیستمی | حالت TUN |
| --- | --- | --- |
| برنامه‌های تحت پوشش | فقط برنامه‌هایی که از پروکسی سیستم پیروی می‌کنند | همهٔ برنامه‌ها |
| DNS | برنامه‌ها همچنان می‌توانند از سرور DNS معمول شما استفاده کنند | با [تنظیمات DNS](@/guides/dns.fa.md#how-dns-works) برنامهٔ Throne مدیریت می‌شود |
| قوانین برای برنامه‌ها (`processName:`، `processPath:`) | فقط به برنامه‌هایی می‌رسند که از پروکسی استفاده می‌کنند | برای همهٔ برنامه‌ها کار می‌کنند |
| مشکلات رایج | برنامه‌هایی که پروکسی را نادیده می‌گیرند | فایروال‌ها، آنتی‌ویروس‌ها یا VPNهای دیگری که جلوی آداپتور را می‌گیرند |

پروکسی سیستمی برای یک مرورگر کافی است. برای برنامه‌هایی که آن را نادیده می‌گیرند، برای تماس‌ها و بازی‌ها و برای قوانین مخصوص یک برنامه از حالت TUN استفاده کنید ([دستورالعمل‌های کاربردی](@/guides/recipes.fa.md#calls-and-games) را ببینید). می‌توانید هر دو حالت را هم‌زمان روشن کنید: برنامه‌هایی که از پروکسی سیستم پیروی می‌کنند از پورت mixed استفاده می‌کنند و حالت TUN بقیه را می‌گیرد.

اگر `برنامه` (Program) ← `آخرین نمایه را به خاطر بسپار` (Remember last profile) روشن باشد، Throne هنگام شروع به کار آخرین نمایه را اجرا می‌کند و اگر `پروکسی سیستمی` (System Proxy) و `حالتvpn` (Tun Mode) هنگام خروج روشن بوده‌اند، آن‌ها را دوباره روشن می‌کند.

## اشتراک‌گذاری پروکسی با دستگاه‌های دیگر {#lan-sharing}

دستگاه‌های دیگر شبکهٔ شما، مانند گوشی‌ها، تلویزیون‌ها یا کنسول‌های بازی، می‌توانند از Throne روی رایانهٔ شما به‌عنوان پروکسی خود استفاده کنند.

1. `برنامه` (Program) ← `به دستگاه های دیگر اجازه اتصال دهید` (Allow other devices to connect) را انتخاب کنید و نمایهٔ در حال اجرا را دوباره راه‌اندازی کنید.
2. نشانی و پورت رایانه‌تان را در نوار وضعیت ببینید، برای مثال `Mixed: 192.168.1.20:2080`.
3. در فایروال خود، اتصال‌های ورودی به این پورت را مجاز کنید: در Windows، وقتی Windows Firewall می‌پرسد، `ThroneCore` را مجاز کنید (یا بعداً در `Allow an app through firewall`)؛ در Linux، برای مثال با `sudo ufw allow 2080`؛ در macOS، وقتی macOS می‌پرسد، اجازه دهید.
4. در دستگاه دیگر، یک پروکسی SOCKS5 یا HTTP با همین نشانی و پورت تنظیم کنید.

{% alert_warning() %}
بدون گذرواژه، هر کسی در شبکهٔ شما می‌تواند از پروکسی شما استفاده کند. `Enable Authorization` را در [تنظیمات ورودی](#inbound-settings) روشن کنید، `Inbound Username` و `Inbound Password` را تنظیم کنید و همین‌ها را در دستگاه‌های دیگر وارد کنید.
{% end %}

دستگاه‌های دیگر، برای مثال یک روتر، می‌توانند از [سرور DNS](@/guides/dns.fa.md#dns-server) برنامهٔ Throne هم استفاده کنند. برای اشتراک‌گذاری کل اتصال به‌صورت هات‌اسپات Wi-Fi، [دستورالعمل‌های کاربردی](@/guides/recipes.fa.md#hotspot) را ببینید.

## تنظیمات ورودی {#inbound-settings}

این تنظیمات پورت mixed را کنترل می‌کنند. `تنظیمات` (Settings) ← `تنظیمات پایه` (Basic Settings) ← `متداول` (Common) را باز کنید و بخش `Inbound Settings` را ببینید. در حالت ساده فقط `پورت شنود` (Listen Port) نمایش داده می‌شود ([حالت ساده و پیشرفته](@/get_started/configuration.fa.md#interface-mode) را ببینید). اگر نمایه‌ای در حال اجراست، برای اعمال تغییرات آن را دوباره راه‌اندازی کنید.

| تنظیم | پیش‌فرض | کارکرد |
| --- | --- | --- |
| `آدرس درحال شنود` (Listen Address) | `127.0.0.1` | `127.0.0.1` فقط برنامه‌های همین رایانه را می‌پذیرد؛ `::` یا `0.0.0.0` دستگاه‌های دیگر را هم می‌پذیرد. `به دستگاه های دیگر اجازه اتصال دهید` (Allow other devices to connect) مقدار `::` را تنظیم می‌کند. |
| `پورت شنود` (Listen Port) | `2080` | پورت mixed، برای SOCKS (4، 4a و 5) و HTTP. |
| `Random port` | خاموش | هر بار هنگام شروع، یک پورت آزاد انتخاب می‌کند که در نوار وضعیت نمایش داده می‌شود. |
| `Enable Authorization` | خاموش | `Inbound Username` و `Inbound Password` را الزامی می‌کند. |
| `Disable Mixed Inbound` | خاموش | پورت mixed را خاموش می‌کند. در این صورت `پروکسی سیستمی` (System Proxy) روشن نمی‌شود و `Use proxy` برای درخواست‌های خود Throne فقط در حالت TUN کار می‌کند. |
| `ورودی سفارشی` (Custom Inbound) | خالی | ورودی‌های اضافی sing-box، به‌صورت یک شیء JSON با فهرست `inbounds`. |
| `قالب پروکسی` (Proxy Format) | `{ip}:{port}` | فقط Windows. `{ip}:{port}` یا `http://{ip}:{port}` یک پروکسی HTTP را اعلام می‌کند و `socks={ip}:{port}` یک پروکسی SOCKS را. |

## در Android {#android}

Throne برای Android یک حالت `VPN` دارد که مانند حالت TUN کار می‌کند و پیش‌فرض است، و یک حالت `فقط به حالت پراکسی` (Proxy only). [حالت‌های VPN و پروکسی](@/android/modes.fa.md) را ببینید.
