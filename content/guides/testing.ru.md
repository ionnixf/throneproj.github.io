Тесты не останавливают запущенный профиль. Профили автовыбора тесты пропускают — вместо этого тестируйте группы, которые использует автовыбор.

## Тест задержки {#url-test}

Тест задержки проверяет, что профиль работает, и измеряет его задержку. Throne дважды запрашивает `URL теста задержки` (Latency Test URL) через профиль и показывает, сколько миллисекунд занял второй запрос.

- **Выбранные профили:** щёлкните их правой кнопкой мыши и выберите `Тест задержки` (Url Test Selected, `Ctrl+Shift+S`).
- **Вся группа:** выберите `Группы` (Groups) → `Тест задержки всей группы` (Url Test Group, `Ctrl+Shift+G`).
- **Запущенный профиль:** щёлкните его имя в левой части строки состояния. Результат появится в строке состояния.

`Остановить тестирование` (Stop Testing, `Ctrl+.`) останавливает идущий тест.

В столбце `Результат теста` (Test Result) отображается задержка (зелёным до 100 мс, жёлтым до 300 мс, красным при большем значении), `Недоступен` (Unavailable), если тест не пройден (в логе есть строка с `ошибка теста` (test error) и причиной), или `Подключение успешно` (Connect OK), если профиль OpenVPN или OpenConnect подключился, но тестовый URL через него не ответил.

Параметры находятся в `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Общие` (Common), в группе `Проверка` (Testing). В простом режиме видны только `URL теста задержки` и `Определять страну выхода` (Look up exit country) (см. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode)).

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `URL теста задержки` (Latency Test URL) | `http://cp.cloudflare.com/` | Адрес, который Throne запрашивает через каждый профиль. |
| `Таймаут` (Timeout; рядом с `Кол-во потоков`) | `3000` мс | Ограничение времени для каждого запроса. При слишком маленьком значении профили с мультиплексированием, которым нужно больше времени на первый запрос, помечаются как нерабочие. |
| `Кол-во потоков` (Concurrency) | `10` | Сколько профилей тестируется одновременно. |
| `URL проверки Direct` (Direct Test URL) | пусто | Адрес, который открывается в вашей сети без прокси. Автовыбор запрашивает его напрямую, чтобы отличить пропавшее подключение к интернету от нерабочих серверов. Пустое значение означает, что Throne использует состояние сети, которое сообщает операционная система. |

## Тест IP и страны {#ip-test}

Этот тест показывает выходной IP-адрес каждого профиля и его страну: именно этот адрес видят сайты. Щёлкните профили правой кнопкой мыши и выберите `Определить выходной IP выбранных` (Resolve Selected Out IP) или выберите `Группы` → `Определить выходной IP группы` (Resolve out IP for group) (только в расширенном режиме). После этого в столбце `Результат теста` отображается флаг страны, а также выходной IP, если включено отображение `Выходной IP` (Out IP) — см. [Сортировка и фильтрация](#sort-filter). Эту страну используют фильтр по странам и параметр автовыбора `Только страны` (Only countries).

После запуска профиля Throne также показывает страну и город его выхода в левом нижнем углу окна и в заголовке окна. В группе `Проверка` параметр `Определять страну выхода` (Look up exit country) отключает это, а `Сервис определения IP` (Lookup service) выбирает сервис; `Автоматически` (Automatic) начинает с IP2Location.io, который использует и тест IP. О сервисах, к которым обращается Throne, см. [Конфиденциальность и сетевые запросы](@/reference/privacy.ru.md#network-requests).

## Тест скорости {#speed-test}

Тест скорости измеряет скорость скачивания и отдачи через профиль.

- **Выбранные профили:** щёлкните их правой кнопкой мыши и выберите `Тест скорости` (Speedtest Selected, `Ctrl+Shift+P`).
- **Вся группа:** выберите `Группы` → `Тест скорости всей группы` (Speedtest Group, `Ctrl+Alt+P`).
- **Текущее подключение:** пока профиль запущен, выберите `Утилиты` (Tools) → `Тест скорости текущего профиля` (Speedtest Current, `F6`).

Throne тестирует профили по одному. В столбце `Результат теста` отображается скорость скачивания после `↓` и скорость отдачи после `↑`, если включено отображение `Скорость` (Speed).

`Настройки` → `Основные настройки` → `Общие` → `Режим проверки скорости` (Speedtest mode) определяет, что делает тест: `Скачивание (↓) + отдача (↑)` (Download + Upload; по умолчанию), `Только скачивание (↓)` (Only Download), `Только отдача (↑)` (Only Upload), `Простое скачивание` (Simple Download; скачивает `URL для простого теста скачивания` (Simple Download URL) без поиска сервера) или `Только проверка страны` (Only Country) — только находит ближайший сервер Speedtest и показывает его страну: быстро, почти без трафика, много профилей одновременно. `Таймаут` рядом с ним (по умолчанию `5000` мс) ограничивает каждую часть теста.

{% alert_warning() %}
Тест скорости передаёт столько данных, сколько успеет до истечения таймаута, — и так для каждого профиля. Тестирование большой группы может израсходовать много трафика.
{% end %}

## Сортировка и фильтрация {#sort-filter}

Щёлкните заголовок столбца, чтобы отсортировать по нему, и ещё раз, чтобы изменить порядок на обратный. При сортировке по задержке вверху оказываются самые быстрые профили, за ними — не прошедшие тест, а в конце — непротестированные. Группа остаётся отсортированной, в том числе после тестов, обновления подписки и импорта, пока вы не щёлкнете заголовок столбца правой кнопкой мыши и не выберете `Отключить сортировку` (Stop Sorting) или не перетащите строку на другое место.

Щёлкните заголовок `Результат теста` правой кнопкой мыши, чтобы выбрать, что показывает столбец (`Выходной IP`, `Скорость`), и по чему он сортируется (`Пингу` (Latency), `Скорости скачивания (↓)` (Download Speed), `Скорости отдачи (↑)` (Upload Speed), `Выходному IP` (IP Out)).

Чтобы отфильтровать список, нажмите `Ctrl+F` и введите текст в поле под заголовком `Тип` (Type), `Адрес` (Address) или `Название` (Name) либо в поле `Фильтр по странам...` (Filter by country...) под заголовком `Результат теста`. В поле `Адрес` запрос `port=443` показывает профили на порту 443, а `port=1000:2000` — профили на портах от 1000 до 2000. Поле страны сравнивается с кодом страны из теста IP или теста скорости, например `DE`. Нажмите `Ctrl+F` ещё раз, чтобы скрыть и очистить поля.

## Очистка {#clean-up}

`Группы` → `Очистка` (Clean up) (это подменю есть и в контекстном меню вкладки группы) удаляет профили из текущей группы:

| Команда | Сочетание клавиш | Что удаляет |
| --- | --- | --- |
| `Удалить дубликаты` (Remove Duplicates) | `Ctrl+Shift+D` | Точные копии более раннего профиля, включая название. |
| `Удалить недоступные` (Remove Unavailable) | `Ctrl+Shift+R` | Профили, последний тест которых не пройден. Запущенный профиль никогда не удаляется. |
| `Удалить недействительные` (Remove Invalid) | `Ctrl+Alt+I` | Профили, которые ядро отклоняет как недействительные. |
| `Удалить небезопасные конфигурации` (Remove Insecure Configs) | – | Профили без шифрования, с TLS без проверки сертификатов или со старыми шифрами Shadowsocks. |

Остальные команды останавливают запущенный профиль, если удаляют его. `Группы` → `Очистить результат теста для группы` (Clear Group test result, `Ctrl+Shift+C`) очищает только результаты тестов.

Чтобы увидеть, какие профили считаются небезопасными, включите `Настройки` → `Основные настройки` → `Интерфейс` (Style) → `Отображать безопасность конфигураций` (Show Config Security; только в расширенном режиме): тогда небезопасные профили помечаются предупреждающим значком в столбце `Тип`.

Для автоматической очистки используйте параметр группы `Автоочистка недоступных профилей` (Auto Clear Unavailable Profiles), который удаляет не прошедшие тест профили после каждого теста задержки группы, или параметры группы подписки из раздела [После каждого обновления](@/guides/subscriptions.ru.md#after-update), которые также могут тестировать и сортировать её.

## Автовыбор {#auto-selector}

Автовыбор — это профиль, который выбирает лучший рабочий профиль из одной или нескольких групп, продолжает проверять остальные и переключается, когда текущий профиль начинает работать хуже или отказывает. Новые серверы из обновления подписки сами добавляются в него.

1. Выберите вкладку группы, которую он должен использовать.
2. Выберите `Программа` (Program) → `Новый профиль` (New profile, `Ctrl+N`). Откроется редактор, в котором в поле `Тип` (Type) уже выбран `Автовыбор` (Auto Selector).
3. Введите `Название` (Name).
4. В поле `Серверы из` (Servers from) отметьте группы, из которых автовыбор выбирает профили. Текущая группа уже отмечена.
5. Нажмите `OK`, затем запустите новый профиль, как любой другой.

| Параметр | Назначение |
| --- | --- |
| `Серверы из` (Servers from) | Группы, профили которых использует автовыбор. Профили всех отмеченных групп ранжируются вместе. |
| `Фильтр по названию` (Only names matching) | Необязательное регулярное выражение; используются только профили, название которых ему соответствует. Совпадение может быть в любом месте названия, регистр не учитывается: `germany\|nl` использует все названия, в которых есть `germany` или `nl`, а `^(?!.*(germany\|🇩🇪)).*$` — все названия, в которых нет ни `germany`, ни 🇩🇪. |
| `Распределить трафик между лучшими профилями` (Share traffic between the best profiles) | Выкл. (по умолчанию): весь трафик идёт через один профиль, а остальные готовые профили находятся в резерве. Вкл.: трафик распределяется между рабочими профилями. |
| `Предпочтительный профиль` (Preferred profile) | Появляется, после того как вы выбрали профиль кнопкой `Использовать этот профиль` (Use this profile) в окне статистики. `Использовать автовыбор` (Use automatic) возвращает выбор автовыбору. |

Каждый профиль работает так, как если бы вы запустили его отдельно: через `Фронт-прокси` (Front Proxy) и `Выходной прокси` (Landing Proxy) своей группы. Эти прокси группы, в которой находится сам автовыбор, не применяются.

`Дополнительно…` (Advanced…) открывает дополнительные параметры; у каждого есть рабочее значение по умолчанию и всплывающая подсказка. Чаще всего меняют эти:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `Только страны` (Only countries) | пусто | Коды стран, например `DE,NL,FR`. `!` исключает страну: `!RU,!IR` использует все страны, кроме этих двух. Используется страна, которую нашёл тест IP или тест скорости, поэтому, пока параметр задан, профили без страны пропускаются. |
| `Запускать лучших` (Run the best) | 300 профилей | Сколько профилей загружается в работающую конфигурацию. Автовыбор переключается между ними без переподключения. |
| `Порог переключения` (Switch tolerance) | 300 мс | Насколько быстрее должен быть другой профиль, чтобы автовыбор переключился на него. |
| `Максимальная задержка` (Maximum latency) | без ограничений | Профили медленнее этого значения никогда не выбираются. |
| `Разрывать подключения при переключении` (Drop connections on switch) | вкл. | После переключения из-за проблемы: вкл. — все соединения сразу переходят на новый профиль; выкл. — начатые загрузки завершаются через старый профиль. |
| `Режим` (Mode) | `Переключение по таймеру (обеспечивает стабильность сеансов)` (Rotate on a timer (keeps sessions stable)) | Используется вместе с `Распределить трафик между лучшими профилями`. В режиме `На каждое подключение (максимальное распределение)` (Per connection (widest spread)) ваш выходной IP может меняться во время сеанса. |

Если пригодных профилей больше, чем задано в `Запускать лучших`, автовыбор сначала выполняет тест задержки для профилей без результата за последние `Срок доверия к результатам` (Trust results for) минут (по умолчанию 1440) и загружает лучшие. Он запускается, как только несколько из них работают, заканчивает тесты в фоне и один раз перезапускается, если рейтинг изменился. Если все запущенные профили не работают, он пересобирается из следующих лучших. Пока у компьютера нет подключения к сети, он приостанавливается. Его строки в логе начинаются с `[Автовыбор]` (`[Auto selector]`).

Пока автовыбор запущен, `Утилиты` → `Статистика автовыбора` (Auto Selector Stats) показывает статус и задержку каждого профиля. `Использовать этот профиль` (Use this profile) оставляет выбранный профиль в работе, `Вернуть автовыбор` (Back to automatic) снова доверяет выбор рейтингу, а `Проверить все сейчас` (Check all now) немедленно измеряет все запущенные профили.

Ограничения:

- Автовыбор не может быть звеном цепочки, а также `Фронт-прокси` (Front Proxy) или `Выходной прокси` (Landing Proxy).
- Он пропускает цепочки, другие профили автовыбора, OpenVPN, OpenConnect, Tailscale, дополнительное ядро (Extra Core), полные конфигурации sing-box, пользовательские конфигурации, которые не удаётся прочитать, и полные конфигурации Xray, которые нельзя совместить с фронт- или выходным прокси своей группы.

## IP-сканер {#ip-scanner}

`Утилиты` (Tools) → `IP-сканер` (IP Scanner) (только в расширенном режиме, см. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode)) проверяет списки IP-адресов и оставляет те, что работают из вашей сети: незаблокированный адрес CDN, за которой находятся ваши серверы, рабочую конечную точку Cloudflare WARP или DNS-резолверы для DNS-туннеля. Результаты образуют IP-список, который группа или профиль могут использовать как [адрес сервера](@/guides/subscriptions.ru.md#server-address).

1. Нажмите `Новое сканирование` (New scan), введите `Название` (Name) и выберите тип сканирования:
   - `Обычное сканирование` (Generic scan) проверяет адреса пингом, TCP, TLS или HTTP, при желании через один из ваших профилей.
   - `Сканирование WARP` (WARP scan) ищет конечные точки WARP, через которые устанавливается соединение WireGuard, AmneziaWG или MASQUE.
   - `Сканирование DNS-резолверов` (DNS resolver scan) ищет резолверы для профиля DNS-туннеля; см. [Сканирование DNS-резолверов](#dns-scan).
2. Нажмите `OK`. Откроется окно сканирования.
3. Задайте цели на вкладке `Цели` (Targets) и проверки на вкладке `Этапы` (Phases).
4. Нажмите `Запустить` (Start). Вкладка `Результаты` (Results) заполняется адресами, прошедшими проверки.

Сканирование продолжается, если закрыть его окно.

На вкладке `Цели`:

- `Исходный список IP` (Base IP list) содержит адреса для сканирования; `Управление` (Manage) открывает [IP-списки](#ip-lists). При сканировании WARP `Использовать встроенные диапазоны WARP` (Use built-in WARP ranges) выбирает список и порты для выбранного режима WARP.
- `Порты` (Ports) объединяются с портами, сохранёнными в списке, если рядом не выбрано иное. Адреса, оставшиеся без порта, сканируются на порту 443, а для обычного HTTP — на порту 80.
- `Лимит результатов` (Stop after (results)) завершает сканирование, когда набирается столько результатов. `Кол-во потоков` (Concurrency) задаёт, сколько адресов проверяется одновременно.
- Адреса IPv6 пропускаются, если не отмечен параметр `Сканировать адреса IPv6` (Scan IPv6 addresses).

На вкладке `Этапы` находятся проверки. Адрес должен пройти все включённые проверки в таком порядке:

| Этап | По умолчанию | Что проверяет |
| --- | --- | --- |
| `ICMP (ping)` | выкл. | Адрес отвечает на пинг. |
| `TCP-подключение` (TCP connect) | вкл. | Порт принимает TCP-соединение. Только для `Обычное сканирование`. |
| `TLS / HTTP` | выкл. | Рукопожатие TLS проходит успешно, и, если `Метод` (Method) не равен `Нет (только хендшейк TLS)` (None (TLS handshake only)), на HTTP-запрос приходит ответ 200 OK. Только для `Обычное сканирование`. |
| `Тест конфигурации` (Config test) | выкл. | Копия профиля, выбранного в поле `Профиль` (Profile), направленная на этот адрес, загружает `URL проверки` (Test URL). Так находятся адреса, которые действительно работают с вашим сервером, например адреса CDN. Только для `Обычное сканирование`. |
| `Тест WARP` (WARP test) | вкл. | Соединение WARP через этот адрес работает в режиме, выбранном в поле `Режим` (Mode): `WireGuard`, `AmneziaWG` или `MASQUE`. Только для `Сканирование WARP`. |

Для `Тест WARP` нужна учётная запись WARP. Вариант по умолчанию, `Отдельный для этого сканирования (рекомендуется)` (Dedicated for this scan (recommended)), требует одного нажатия `Зарегистрировать` (Register): так в Cloudflare регистрируется новое устройство WARP.

На вкладке `Результаты` кнопка `Сохранить как список IP` (Save as IP list) копирует результаты в новый IP-список.

Если у сканирования уже есть результаты, `Запустить` спрашивает, что делать: `Сканировать с начала` (Scan from the beginning) очищает результаты и снова сканирует исходный список; `Перепроверить текущие результаты` (Rescan current results) проверяет заново только результаты и удаляет те, что перестали работать.

### Сканирование DNS-резолверов {#dns-scan}

Сканирование DNS-резолверов ищет DNS-резолверы, которые пропускают туннель одного из ваших профилей [DNS-туннеля](@/advanced/dns_tunnels.ru.md): DNSTT (в том числе в режиме VayDNS), MasterDNS или VLESS (Xray) с XDNS. Оно пробует каждый адрес исходного списка как единственный резолвер этого профиля и оставляет резолверы, прошедшие проверку.

Чтобы создать его, выберите `Сканирование DNS-резолверов` (DNS resolver scan) в окне `Новое сканирование` (New scan) или нажмите `Найти резолверы…` (Find resolvers…) рядом с `Список IP` (IP list) в редакторе сохранённого профиля DNS-туннеля — так открывается или создаётся сканирование для этого профиля. Сканирование проверяет профиль в том виде, в каком он был сохранён в последний раз.

На вкладке `Цели` (Targets) выберите резолверы для проверки в поле `Исходный список IP` (Base IP list), например `Iran DNS resolvers` или `Russia DNS resolvers`. Поля `Порты` (Ports) нет: каждый адрес проверяется на порту, сохранённом в списке, или на порту 53.

На вкладке `Этапы` (Phases) есть одна проверка, `Проверка DNS-туннеля` (DNS tunnel test), с полями `Профиль` (Profile), `Проверка` (Test) и `Таймаут (мс)` (Timeout (ms)) на всю проверку одного резолвера. Для каждого типа профиля проверка выполняет и проверки, указанные перед ней:

| Проверка | Профили | Что проверяет |
| --- | --- | --- |
| `Опрос: пропускает один запрос туннеля` (Poll: relays one tunnel query) | DNSTT, XDNS | Резолвер передаёт один запрос туннеля серверу туннеля и возвращает правильный ответ. |
| `Имена запросов: также пропускает имена той же длины, что отправляет профиль` (Query names: also relays names as long as the profile sends) (по умолчанию) | DNSTT, XDNS | Резолвер также пропускает имена запросов той же длины, что отправляет профиль. Сканирование находит самое длинное имя, которое пропускает резолвер. |
| `Хендшейк: также открывает сеанс туннеля` (Handshake: also opens a tunnel session) | DNSTT | Через резолвер открывается сеанс туннеля с сервером. |
| `Быстрая: пропускает самые маленькие пакеты` (Quick: relays the smallest packets) (по умолчанию) | MasterDNS | Резолвер пропускает запросы и ответы самого маленького размера, который нужен профилю. |
| `Полная: также измеряет MTU отправки и приема` (Full: also measures the upload and download MTU) | MasterDNS | Сканирование также находит самый большой запрос и ответ, которые пропускает резолвер. |

На вкладке `Результаты` (Results) `Задержка` (Latency) — это время ответа резолвера. `Макс. QNAME` (Max QNAME; DNSTT и XDNS) — самое длинное имя запроса, которое пропускает резолвер, в единицах `Макс. длина QNAME` (Max QNAME Length) для DNSTT и `lenLimit` для XDNS. `MTU отправки` (Upload MTU) и `MTU приема` (Download MTU) (MasterDNS) — самый большой объём данных в одном запросе и в одном ответе. Резолверы, не прошедшие проверку, не сохраняются; лог показывает, на каком этапе остановился каждый из них.

Нажмите `Использовать как резолверы` (Use as resolvers) на вкладке `Результаты`, чтобы список результатов сканирования стал `Список IP` (IP list) профиля. Резолверы, введённые в профиле, остаются и используются первыми. Профиль читает список при каждом запуске, поэтому следует за сканированием: `Сканировать с начала` (Scan from the beginning) очищает список, а `Перепроверить текущие результаты` (Rescan current results) удаляет резолверы, которые перестали работать. Для неизменного набора нажмите `Сохранить как список IP` (Save as IP list) и выберите этот список в поле `Список IP` профиля.

### IP-списки {#ip-lists}

Нажмите `Списки IP` (IP Lists) в окне `IP-сканер`, чтобы управлять списками, которые читают сканирования и используют группы и профили. Сразу есть списки `Cloudflare CDN`, `Fastly CDN`, `Gcore CDN`, `Cloudflare WARP (WireGuard)`, `Cloudflare WARP (MASQUE)`, `Iran DNS resolvers` и `Russia DNS resolvers`. `Импорт` (Import) → `Добавить списки по умолчанию` (Add default lists) восстанавливает их.

- `Создать` (New) создаёт список. Его `Источник` (Source) — `Вручную` (Manual) (записи пишете вы), `URL` (адрес, который загружает Throne) или `Набор правил` (Rule-set) (диапазоны IP набора правил, например `geoip-ir`, или URL набора правил). Список `URL` или `Набор правил` может сам обновляться через `Автообновление` (Auto update) с интервалом не меньше 30 минут.
- Пишите по одной записи на строку, например `1.2.3.4`, `1.2.3.0/24`, `1.2.3.4:443`, `[2606:4700::1]:443`, `1.2.3.0/24 443` или `1.2.3.1-1.2.3.9`.

Результаты каждого сканирования тоже образуют список с пометкой «Результат сканирования» (Result of scan) и названием сканирования. Группа или профиль могут использовать его напрямую, но `Сканировать с начала` его очищает; для списка, который не меняется, используйте `Сохранить как список IP`.

## На Android {#android}

В Throne для Android те же тесты и тот же автовыбор. Отличия:

- **Меню.** На экране `Конфигурация` (Profiles) в меню `⋮` есть `Тест` (Test) (`URL-тест` (URL test), `Тест IP и страны` (IP & country test), `Тест скорости` (Speed test), `Остановить тест` (Stop testing)), `Удалить` (Remove) и `Сортировка` (Sort). Для выбранных профилей используйте `Тест` в меню выделения, для одного профиля — его кнопку `⋮`.
- **Панель тестирования.** Панель показывает ход и результаты теста, а также действия, например `Сортировать по задержке` (Sort by latency), `Удалить недоступные` (Remove unavailable) и `Подключиться к самому быстрому` (Connect to fastest).
- **Текущее подключение.** Пока подключение активно, нажмите на панель статистики, чтобы проверить подключение. Долгое нажатие на неё открывает `Графики в реальном времени` (Live graphs) и `Тест скорости текущего соединения` (Speed test current connection). Панель также показывает страну выхода; в `Настройки` (Settings) → `Тестирование` (Testing) есть `Look up exit country` и `Lookup service`.
- **Автовыбор.** Создайте его через `Добавить профиль` (Add profile) → `Ручные настройки` (Manual settings) → `Автовыбор` (Auto selector). Нажмите на его строку состояния на экране `Конфигурация`, чтобы открыть `Статистика автовыбор` (Auto selector stats).
- **IP-сканер.** На Android его нет.
