پیش از آنکه یک برنامه بتواند سایتی را باز کند، یک جست‌وجوی DNS نام سایت را به نشانی IP تبدیل می‌کند. این صفحه توضیح می‌دهد Throne برای هر جست‌وجو از کدام سرور DNS استفاده می‌کند، تنظیمات زبانهٔ `دی‌ان‌اس` (DNS) چه کاری انجام می‌دهند و نتیجهٔ تست نشت DNS را چگونه بخوانید. تنظیمات پیش‌فرض برای بیشتر افراد کار می‌کنند.

## DNS در Throne چگونه کار می‌کند {#how-dns-works}

Throne درون هسته، حل‌کنندهٔ DNS (resolver) مخصوص به خود را دارد. این حل‌کننده از سه سرور DNS استفاده می‌کند:

| سرور | مسیر پرس‌وجوها | کاربرد |
| --- | --- | --- |
| `دی ان اس سمت-سرور` (Remote DNS) | از طریق پروکسی | به پرس‌وجوهای DNS برنامه‌ها پاسخ می‌دهد، مگر اینکه یکی از قوانین زیر آن‌ها را به جای دیگری بفرستد. |
| `دی ان اس مستقیم` (Direct DNS) | مستقیم، بدون پروکسی | به پرس‌وجوهای دامنه‌هایی پاسخ می‌دهد که نمایهٔ مسیریابی شما آن‌ها را `direct` می‌فرستد. Throne برای یافتن نشانی سرور پروکسی شما نیز از آن استفاده می‌کند، و همچنین برای یافتن نشانی یک سایت، وقتی مستقیماً و با نام به آن سایت وصل می‌شود. |
| `Local Override` | مستقیم | نام دو سرور بالا را، برای نمونه `dns.google`، به نشانی IP تبدیل می‌کند. خالی یعنی حل‌کنندهٔ DNS سیستم‌عامل شما. |

وقتی پرس‌وجوی یک برنامه به Throne می‌رسد، Throne به این ترتیب به آن پاسخ می‌دهد:

1. `Predefined Answers` و `Respect Hosts File` اول پاسخ می‌دهند.
2. با `فعال کردن IP جعلی` (Enable FakeIP)، پرس‌وجوهای نشانی یک نشانی جعلی دریافت می‌کنند ([FakeIP](#fakeip) را ببینید).
3. با `Enable DNS Routing` (که به‌طور پیش‌فرض روشن است)، دامنه‌هایی که نمایهٔ مسیریابی شما `direct` می‌فرستد به DNS مستقیم می‌روند. این شامل قوانین `domain:`، `suffix:`، `keyword:` و `regex:` و مجموعه‌قوانین داخلی `geosite-*` می‌شود، اما مجموعه‌قوانین `geoip-*`، قوانین IP و فایل‌های `.srs` خودتان را شامل نمی‌شود.
4. هر چیز دیگر به `سرور دی‌ان‌اس پیش‌فرض` (Default DNS server) می‌رود که به‌طور پیش‌فرض `remote` است. اگر آن را روی `direct` بگذارید، دامنه‌هایی که نمایهٔ مسیریابی شما به `proxy` می‌فرستد، با همان شرایط مرحلهٔ 3، همچنان از DNS سمت‌سرور استفاده می‌کنند.

منشأ پرس‌وجوها به حالت اتصال بستگی دارد:

- **حالت TUN.** پرس‌وجوهای DNS برنامه‌های شما وارد تونل می‌شوند و به Throne می‌رسند. Throne یک مرحلهٔ DNS به هر نمایهٔ مسیریابی ساخت‌یافته اضافه می‌کند (قانون `Route DNS` یا `dns-hijack` در فهرست هم همین کار را انجام می‌دهد)، بنابراین همان‌طور که در بالا توضیح داده شد به این پرس‌وجوها پاسخ می‌دهد. یک نمایهٔ مسیریابی خام فقط در صورتی این مرحله را دارد که خودتان آن را بنویسید؛ [نمایه‌های خام](@/guides/routing.fa.md#raw-profiles) را ببینید. در macOS، از نسخهٔ 1.4.0، تا وقتی حالت TUN در حال اجراست، هسته آداپتور TUN را به‌عنوان یک سرویس شبکهٔ جداگانه با یک سرور DNS درون تونل به macOS اضافه می‌کند. سرورهای DNS سرویس‌های شبکهٔ شما، مثلاً `Wi-Fi`، را تغییر نمی‌دهد. [حالت TUN](@/guides/tun_mode.fa.md#side-effects-dns) را ببینید.
- **حالت پروکسی سیستمی.** برنامه‌هایی که از پروکسی استفاده می‌کنند، نام سایت را به Throne می‌فرستند. برای اتصال‌هایی که از پروکسی می‌گذرند، سرور پروکسی نشانی نام را پیدا می‌کند. برای اتصال‌های مستقیم، Throne آن را با DNS مستقیم پیدا می‌کند. برنامه‌ها همچنین می‌توانند خودشان با حل‌کنندهٔ DNS سیستم‌عامل شما نام‌ها را جست‌وجو کنند. این جست‌وجوها از Throne عبور نمی‌کنند.

## تنظیمات {#settings}

`تنظیمات` (Settings) ← `تنظیمات مسیریابی` (Routing Settings) ← `دی‌ان‌اس` (DNS) را باز کنید. تغییرات پس از کلیک روی `تایید` (OK) و راه‌اندازی دوبارهٔ اتصال اعمال می‌شوند. نمایهٔ مسیریابی فعال می‌تواند برخی از این تنظیمات را با تنظیمات خودش جایگزین کند؛ [DNS برای هر نمایهٔ مسیریابی](#route-dns) را ببینید.

در حالت ساده، زبانهٔ `دی‌ان‌اس` (DNS) وجود ندارد: `دی ان اس سمت-سرور` (Remote DNS)، `دی ان اس مستقیم` (Direct DNS) و `سرور دی‌ان‌اس پیش‌فرض` (Default DNS server) در بخش `تنظیمات دی ان اس ساده` (Simple DNS Settings) از زبانهٔ `متداول` (Common) قرار دارند، و تنظیمات دیگر پنهان‌اند اما مقدارشان را نگه می‌دارند. اگر `Use Custom DNS Object` روشن باشد، زبانهٔ `دی‌ان‌اس` (DNS) باقی می‌ماند تا بتوانید آن را خاموش کنید. [حالت ساده و پیشرفته](@/get_started/configuration.fa.md#interface-mode) را ببینید.

| تنظیم | پیش‌فرض | کارکرد |
| --- | --- | --- |
| `دی ان اس سمت-سرور` (Remote DNS) | `https://8.8.8.8/dns-query` | سروری که از طریق پروکسی استفاده می‌شود. فهرست همچنین `tls://8.8.8.8`، `tls://1.1.1.1`، `8.8.8.8` و `1.1.1.1` را پیشنهاد می‌دهد. |
| `دی ان اس مستقیم` (Direct DNS) | `localhost` | سروری که بدون پروکسی استفاده می‌شود. `localhost` یعنی حل‌کنندهٔ DNS سیستم‌عامل شما. آن را نگه دارید، مگر اینکه کار نکند؛ در آن صورت سروری را انتخاب کنید که در شبکهٔ شما بدون پروکسی کار می‌کند. فهرست، حل‌کننده‌های عمومی در چین (`223.5.5.5`، `119.29.29.29`)، ایران (`178.22.122.100`) و روسیه (`77.88.8.8`) را پیشنهاد می‌دهد. |
| `Disable IPv6` (کنار هر سرور) | خاموش | به پرس‌وجوهای IPv6 (AAAA) که به آن سرور فرستاده می‌شوند، پاسخ خالی می‌دهد. |
| `Local Override` | خالی | سرور DNS‌ای که برای تبدیل نام سرورهای DNS شما به نشانی IP استفاده می‌شود. وقتی نمی‌توان از حل‌کنندهٔ DNS سیستم‌عامل استفاده کرد، یک نشانی IP اینجا تنظیم کنید. |
| `سرور دی‌ان‌اس پیش‌فرض` (Default DNS server) | `remote` | سرور پرس‌وجوهایی که هیچ قانون دیگری به آن‌ها رسیدگی نمی‌کند: `remote` یا `direct`. |
| `Enable DNS Routing` | روشن | پرس‌وجوهای دامنه‌هایی را که `direct` می‌روند، به DNS مستقیم می‌فرستد. |
| `Respect Hosts File` | خاموش | ابتدا از فایل hosts سیستم شما به پرس‌وجوهای A و AAAA پاسخ می‌دهد. فقط دامنه‌هایی که در این فایل فهرست شده‌اند تحت تأثیر قرار می‌گیرند. |
| `Predefined Answers` | روشن | پاسخ‌های ثابت با نحو فایل hosts. ورودی پیش‌فرض `127.0.0.1 localhost` است. |
| `فعال کردن IP جعلی` (Enable FakeIP) | خاموش | [FakeIP](#fakeip) را ببینید. |
| `FakeIP Disable IPv6` | خاموش | هیچ نشانی IPv6 جعلی نمی‌دهد؛ پرس‌وجوهای AAAA پاسخ خالی می‌گیرند. |

از نسخهٔ 1.4.0، فهرست‌های `دی ان اس سمت-سرور` (Remote DNS) و `دی ان اس مستقیم` (Direct DNS)، بالاتر از نمونه‌های داخلی، 8 سروری را هم که آخرین بار در آن‌ها تایپ کرده‌اید پیشنهاد می‌دهند؛ تازه‌ترین در بالا.

`دی ان اس سمت-سرور` (Remote DNS)، `دی ان اس مستقیم` (Direct DNS) و `Local Override` این قالب‌ها را می‌پذیرند:

| قالب | مثال |
| --- | --- |
| DNS ساده | `8.8.8.8` یا `8.8.8.8:53` |
| DNS روی TCP | `tcp://8.8.8.8:53` |
| DNS روی TLS | `tls://1.1.1.1` |
| DNS روی HTTPS | `https://1.1.1.1/dns-query` |
| DNS روی HTTP/3 | `h3://dns.example.com/dns-query` |
| DNS روی QUIC | `quic://dns.example.com` |
| سروری که شبکهٔ شما در اختیار می‌گذارد | `dhcp://auto` |
| حل‌کنندهٔ DNS سیستم‌عامل شما (برای `دی ان اس مستقیم`) | `localhost` |

وقتی نمایهٔ در حال اجرا از Xray استفاده می‌کند و `دی ان اس سمت-سرور` (Remote DNS) از نوع DNS ساده یا DNS روی QUIC است، Throne به‌جای آن از DNS روی HTTPS استفاده می‌کند. برای نمونه، `1.1.1.1` به `https://1.1.1.1/dns-query` تبدیل می‌شود؛ سروری که Throne نمی‌شناسد به `https://8.8.8.8/dns-query` تبدیل می‌شود.

`Predefined Answers` ویرایشگری باز می‌کند که در آن هر ورودی در یک خط نوشته می‌شود:

```text
127.0.0.1 localhost
10.0.0.5 nas.lan files.lan
```

دامنه‌ای که در این فهرست فقط یک نشانی IPv4 دارد، برای پرس‌وجوهای IPv6 پاسخ «no such domain» (چنین دامنه‌ای وجود ندارد) می‌گیرد، و برعکس. به این ترتیب برنامه‌ها نمی‌توانند ورودی شما را دور بزنند.

## FakeIP {#fakeip}

با `فعال کردن IP جعلی` (Enable FakeIP)، Throne بی‌درنگ و بدون پرسیدن از یک سرور DNS واقعی، به پرس‌وجوهای نشانی با یک نشانی جعلی از `198.18.0.0/15` (در IPv6: `2001:db8::/32`) پاسخ می‌دهد. وقتی برنامه به آن نشانی وصل می‌شود، Throne می‌داند این نشانی نمایندهٔ کدام دامنه است و اتصال را بر اساس نام مسیریابی می‌کند. جست‌وجوی واقعی بعداً انجام می‌شود: برای اتصال‌هایی که از پروکسی می‌گذرند روی سرور پروکسی، و برای اتصال‌های مستقیم با DNS مستقیم.

این کار دو مزیت دارد:

- اتصال‌ها سریع‌تر آغاز می‌شوند، چون برنامه‌ها منتظر پاسخ واقعی DNS نمی‌مانند.
- هیچ پرس‌وجوی DNS پیش از مسیریابی اتصال از دستگاه شما خارج نمی‌شود.

FakeIP فقط روی پرس‌وجوهایی اثر دارد که به Throne می‌رسند، پس در حالت TUN مفید است. برای برنامه‌ها در حالت پروکسی سیستمی چیزی را تغییر نمی‌دهد.

نکته‌هایی که باید بدانید:

- پاسخ‌های `Predefined Answers` و فایل hosts واقعی باقی می‌مانند.
- برنامه‌ها نشانی‌های جعلی را در حافظهٔ نهان (cache) خودشان نگه می‌دارند. پس از متوقف کردن Throne، برنامه‌ای که هنوز یک نشانی جعلی نگه داشته است، تا وقتی نام را دوباره جست‌وجو نکند نمی‌تواند وصل شود. اگر برنامه‌ای همچنان آفلاین ماند، آن را دوباره راه‌اندازی کنید.
- `Advanced Settings` → `Save Cache To File` نشانی‌های جعلی را هنگام راه‌اندازی دوبارهٔ Throne نگه می‌دارد.
- پیش از نسخهٔ 1.4.0، نشانی‌های جعلی IPv6 از `fc00::/18` می‌آمدند. در حالت TUN، `Private Range Bypass` آن‌ها را بیرون از تونل می‌فرستاد، پس برنامه‌هایی که اول IPv6 را امتحان می‌کردند نمی‌توانستند وصل شوند. از نسخهٔ 1.4.0، این نشانی‌ها از `2001:db8::/32` می‌آیند، محدوده‌ای که هرگز در اینترنت استفاده نمی‌شود.

## پیشرفته {#advanced}

`Advanced Settings` در زبانهٔ `دی‌ان‌اس` (DNS) حافظهٔ نهان DNS را کنترل می‌کند:

| تنظیم | پیش‌فرض | کارکرد |
| --- | --- | --- |
| `Cache Capacity` | `65536` | حافظهٔ نهان چند پاسخ را نگه می‌دارد. |
| `Query Timeout` | `10s` | مدت انتظار برای پاسخ یک سرور DNS. |
| `Optimistic Cache` | خاموش | تا زمانی که یک پاسخ منقضی‌شده در پس‌زمینه تازه می‌شود، همچنان همان را ارائه می‌دهد. با `Disable Cache` یا `Disable Expire` قابل ترکیب نیست. |
| `Optimistic Timeout` | `3d` | یک پاسخ منقضی‌شده تا چه مدت هنوز می‌تواند ارائه شود. |
| `Disable Cache` | خاموش | حافظهٔ نهان DNS را خاموش می‌کند. |
| `Disable Expire` | خاموش | پاسخ‌های ذخیره‌شده را پس از انقضا نگه می‌دارد. |
| `Save Cache To File` | خاموش | پاسخ‌های ذخیره‌شده و نشانی‌های FakeIP را در فایل حافظهٔ نهان هسته می‌نویسد تا پس از راه‌اندازی دوباره باقی بمانند. هر ورودی یک بار نوشتن روی دیسک هزینه دارد. |
| `Reverse Mapping` | خاموش | به خاطر می‌سپارد هر نشانی IP پاسخ‌داده‌شده به کدام دامنه تعلق دارد تا قوانین دامنه بتوانند با اتصال‌ها به آن نشانی منطبق شوند. |

مدت‌زمان‌ها به‌صورت یک عدد و پس از آن یکی از `ns`، `us`، `ms`، `s`، `m`، `h` یا `d` نوشته می‌شوند، برای نمونه `5s` یا `3d`.

`Use Custom DNS Object` همهٔ موارد این زبانه را با یک شیء کامل `dns` برای sing-box جایگزین می‌کند که آن را با `Edit DNS Object` می‌نویسید. تا وقتی این گزینه روشن است، تنظیمات ساده و `Advanced Settings` خاکستری (غیرفعال) می‌شوند، و قابلیت‌هایی مانند مسیریابی DNS، FakeIP و پاسخ‌های ازپیش‌تعریف‌شده فقط در صورتی کار می‌کنند که شیء شما آن‌ها را راه‌اندازی کند. در ویرایشگر، `فرمت` (Format) JSON را مرتب می‌کند و `اسناد` (Document) نشانی [مستندات DNS در sing-box](https://sing-box.sagernet.org/configuration/dns/) را نشان می‌دهد.

{% alert_warning() %}
در شیء DNS سفارشی، سروری با برچسب (tag) `dns-direct` نگه دارید. مسیریابی Throne از آن برای یافتن نشانی سرورها استفاده می‌کند.
{% end %}

## DNS برای هر نمایهٔ مسیریابی {#route-dns}

از نسخهٔ 1.4.0، یک نمایهٔ مسیریابی می‌تواند سرورهای DNS مخصوص به خودش را داشته باشد. تا وقتی آن نمایه، نمایهٔ مسیریابی فعال است، این سرورها جای سرورهای سراسری زبانهٔ `دی‌ان‌اس` (DNS) را می‌گیرند. این کار وقتی مفید است که نمایه‌ای برای یک کشور به یک DNS مستقیم نیاز دارد که در همان کشور کار کند، یا وقتی یک ارائه‌دهنده نمایهٔ مسیریابی را همراه با سرورهای DNS‌اش در اختیار می‌گذارد.

1. `تنظیمات` (Settings) ← `تنظیمات مسیریابی` (Routing Settings) ← `مسیر` (Route) را باز کنید، نمایه را انتخاب کنید و روی `Edit` کلیک کنید. یا روی نمایه در پایین منوی `مسیریابی` (Routing) راست‌کلیک کنید.
2. زبانهٔ `DNS` را باز کنید و `Use custom DNS settings` را انتخاب کنید.
3. تنظیمات را تغییر دهید و سپس روی `تایید` (OK) کلیک کنید.

این زبانه این تنظیمات [زبانهٔ DNS](#settings) را، با برچسب‌های انگلیسی، دارد: `Remote DNS`، `Direct DNS`، کادرهای `Disable IPv6` آن‌ها، `Default DNS server`، `Enable DNS Routing`، `Enable FakeIP` و `FakeIP Disable IPv6`. نخستین باری که به `Use custom DNS settings` می‌روید، این تنظیمات با مقادیر سراسری آغاز می‌شوند. `Use the global DNS settings`، که پیش‌فرض است، مقادیر سراسری را خاکستری (غیرفعال) نشان می‌دهد. `Local Override`، `Respect Hosts File`، `Predefined Answers` و `Advanced Settings` همیشه از زبانهٔ `دی‌ان‌اس` (DNS) می‌آیند.

نکته‌هایی که باید بدانید:

- انتخاب نمایهٔ مسیریابی دیگری در منوی `مسیریابی` (Routing) اتصال را دوباره راه‌اندازی می‌کند، پس سرورهای DNS هم همراه با آن عوض می‌شوند.
- از نسخهٔ 1.4.0، یک گروه می‌تواند از نمایهٔ مسیریابی خودش استفاده کند ([نمایهٔ مسیریابی برای هر گروه](@/guides/routing.fa.md#group-routing) را ببینید). در این صورت، تا وقتی نمایه‌ای از آن گروه در حال اجراست، تنظیمات DNS همان نمایهٔ مسیریابی اعمال می‌شوند. تست‌ها همیشه از تنظیمات DNS نمایهٔ مسیریابی‌ای استفاده می‌کنند که در منوی `مسیریابی` (Routing) انتخاب شده است، چون ممکن است نمایه‌هایی از چند گروه را تست کنند.
- نمایهٔ مسیریابی‌ای که یک [اشتراک فراهم می‌کند](@/guides/routing.fa.md#subscription-routing) هرگز تنظیمات DNS را از اشتراک نمی‌گیرد. اگر به تنظیمات DNS نیاز دارد، در زبانهٔ `DNS` آن، تنظیمات خودش را به آن بدهید؛ به‌روزرسانی‌های اشتراک آن‌ها را نگه می‌دارند.
- نمایه‌ای که تنظیمات DNS خودش را دارد، جای [شیء DNS سفارشی](#advanced) را هم می‌گیرد: تا وقتی چنین نمایه‌ای فعال است، Throne گزینهٔ `Use Custom DNS Object` را نادیده می‌گیرد. وقتی نمایه‌ای از تنظیمات سراسری پیروی می‌کند و `Use Custom DNS Object` روشن است، زبانهٔ `DNS` آن نمایه می‌گوید که آن شیء اعمال می‌شود.
- نمایه‌های مسیریابی ساخت‌یافته، راه‌دور و خام همگی این زبانه را دارند. یک نمایهٔ راه‌دور هنگام به‌روزرسانی، تنظیمات DNS خودش را نگه می‌دارد؛ Throne هرگز آن‌ها را از URL نمی‌گیرد.
- لینک `throne://route/` یک نمایه، تنظیمات DNS آن را در خود دارد. پیش از آنکه چنین لینکی را با `Import` در `تنظیمات مسیریابی` (Routing Settings) وارد کنید، Throne سرورها را نام می‌برد: «It uses its own DNS servers: remote …, direct …» (از سرورهای DNS خودش استفاده می‌کند: راه‌دور …، مستقیم …). آن‌ها را بررسی کنید: این سرورها تا وقتی نمایه فعال است، همهٔ نام‌هایی را که جست‌وجو می‌کنید می‌بینند. [اشتراک‌گذاری نمایه‌ها](@/guides/routing.fa.md#share-profiles) را ببینید.
- در حالت ساده، زبانهٔ `DNS` یک نمایه فقط وقتی نمایان می‌شود که نمایه از قبل تنظیمات DNS خودش را داشته باشد.

## سرور DNS برای دستگاه‌های دیگر {#dns-server}

تا وقتی نمایه‌ای در حال اجراست، هستهٔ Throne یک سرور DNS هم اجرا می‌کند. این سرور با تنظیمات DNS همین صفحه، از جمله تنظیمات نمایهٔ مسیریابی، پاسخ می‌دهد. پورت آن `تنظیمات` (Settings) ← `تنظیمات پایه` (Basic Settings) ← `Miscellaneous` → `Sing-box` → `DNS Server Port` است، به‌طور پیش‌فرض `5533`، برای TCP و UDP (فقط در حالت پیشرفته؛ [حالت ساده و پیشرفته](@/get_started/configuration.fa.md#interface-mode) را ببینید). این سرور به‌طور پیش‌فرض فقط روی `127.0.0.1` گوش می‌دهد، پس فقط برنامه‌های همین رایانه می‌توانند از آن استفاده کنند.

از نسخهٔ 1.4.0، دستگاه‌های دیگر شبکهٔ شما هم می‌توانند از آن استفاده کنند، برای مثال روتری که پرس‌وجوهای DNS خود را از راه این رایانه می‌فرستد:

1. `به دستگاه های دیگر اجازه اتصال دهید` (Allow other devices to connect) را زیر `DNS Server Port` تیک بزنید (به‌طور پیش‌فرض خاموش است)، سپس روی `تایید` (OK) کلیک کنید.
2. اگر نمایه‌ای در حال اجراست، در اعلان «Settings changed, restart to apply» (تنظیمات تغییر کرد؛ برای اعمال، دوباره راه‌اندازی کنید) روی `Restart` کلیک کنید. سپس سرور DNS روی همهٔ رابط‌های شبکه گوش می‌دهد.
3. در فایروال خود، اتصال‌های ورودی TCP و UDP به این پورت را مجاز کنید، همانند [اشتراک‌گذاری در شبکهٔ محلی](@/guides/proxy_modes.fa.md#lan-sharing). برای مثال در Linux با ufw: `sudo ufw allow 5533`.
4. در دستگاه دیگر، سرور DNS را روی نشانی LAN رایانهٔ خود و همین پورت بگذارید، برای مثال `192.168.1.20` و `5533`.

نکته‌هایی که باید بدانید:

- بسیاری از گوشی‌ها و رایانه‌ها برای DNS فقط یک نشانی می‌پذیرند و همیشه از پورت 53 استفاده می‌کنند. این تنظیم برای دستگاه‌هایی مناسب است که اجازهٔ وارد کردن پورت را هم می‌دهند، مانند بسیاری از روترها.
- هر کسی که به این پورت دسترسی داشته باشد، می‌تواند نام‌ها را از راه تنظیمات DNS شما، و در نتیجه از راه پروکسی شما، جست‌وجو کند. فقط در شبکه‌ای که به آن اعتماد دارید از آن استفاده کنید.
- این سرور فقط به پرس‌وجوهای DNS پاسخ می‌دهد. اتصال‌های دیگر به این پورت رد می‌شوند.
- با `فعال کردن IP جعلی` (Enable FakeIP)، دستگاه‌های دیگر هم نشانی‌های جعلی می‌گیرند. این نشانی‌ها فقط برای اتصال‌هایی کار می‌کنند که از Throne می‌گذرند.
- این تنظیم از `برنامه` (Program) ← `به دستگاه های دیگر اجازه اتصال دهید` (Allow other devices to connect) جداست که پورت پروکسی را به اشتراک می‌گذارد.
- با [thronectl](@/advanced/api.fa.md#settings)، برای مثال در [Throne بدون رابط گرافیکی](@/headless/_index.fa.md)، این تنظیم `dns_in_lan` و پورت آن `dns_in_port` است.

## تست‌های نشت DNS {#leak-tests}

تست نشت DNS وب‌سایتی است که نشان می‌دهد کدام سرورهای DNS نام‌های آزمایشی آن را جست‌وجو کرده‌اند. نتیجه به حالت اتصال و نمایهٔ مسیریابی شما بستگی دارد.

این نتیجه‌ها مورد انتظارند:

- **ارائه‌دهندهٔ DNS سمت‌سرور شما** (با تنظیم پیش‌فرض، Google). پرس‌وجوهای شما از طریق DNS سمت‌سرور و پروکسی رفته‌اند. این نتیجهٔ عادی برای سایت‌هایی است که از پروکسی عبور می‌دهید. اگر نمایهٔ مسیریابی فعال [تنظیمات DNS خودش](#route-dns) را داشته باشد، به‌جای آن سرورهای همان نمایه را می‌بینید.
- **ارائه‌دهندهٔ اینترنت شما، برای سایت‌هایی که مستقیم می‌روند.** Throne دامنه‌هایی را که مستقیم می‌روند با DNS مستقیم جست‌وجو می‌کند که به‌طور پیش‌فرض همان حل‌کنندهٔ DNS سیستم‌عامل شماست و معمولاً به ارائه‌دهندهٔ اینترنت شما تعلق دارد. در حالت پروکسی سیستمی، یا با FakeIP، این اتفاق برای سایت‌هایی هم می‌افتد که فقط به این دلیل مستقیم می‌روند که خروجی پیش‌فرض نمایهٔ مسیریابی `direct` است، مانند نمایه‌های «Proxy … Blocked». ترافیک مستقیم در هر حال بدون پروکسی به سایت می‌رسد، پس ارائه‌دهندهٔ شما در هر صورت آن را می‌بیند.
- **ارائه‌دهندهٔ اینترنت شما، در حالت پروکسی سیستمی.** مرورگرها و برنامه‌ها می‌توانند خودشان، بیرون از Throne، نام‌ها را جست‌وجو کنند. اگر این موضوع برایتان مهم است، از حالت TUN استفاده کنید.
- **ارائه‌دهندهٔ خود مرورگر،** وقتی مرورگر از DNS امن (DNS روی HTTPS) استفاده می‌کند. این جست‌وجوها اتصال‌های HTTPS معمولی هستند که از قوانین مسیریابی شما پیروی می‌کنند.
- **ارائه‌دهندهٔ اینترنت شما برای بیشتر نام‌ها،** وقتی `سرور دی‌ان‌اس پیش‌فرض` (Default DNS server) روی `direct` باشد.

یک مشکل واقعی این‌گونه است: از حالت TUN و نمایهٔ مسیریابی‌ای استفاده می‌کنید که سایت تست را از پروکسی عبور می‌دهد (برای نمونه `Default`)، اما تست همچنان ارائه‌دهندهٔ اینترنت شما را نشان می‌دهد. در این صورت برخی پرس‌وجوها تونل را دور می‌زنند. در Windows، بررسی کنید که `تنظیمات` (Settings) ← `تنظیمات vpn` (Tun Settings) ← `مسیر سخت‌گیرانه` (Strict Route) روشن باشد (پیش‌فرض در Windows 10 و نسخه‌های بعدی)، و راهنمای [محافظت از نشت DNS در Windows](@/advanced/windows_tun_mode.fa.md#strict-route) را دنبال کنید.

تست‌های WebRTC چیز دیگری را بررسی می‌کنند: نشانی IP شما را، نه DNS شما را. تست WebRTC که هیچ نشانی IP عمومی نشان ندهد، مشکلی ندارد ([#1267](https://github.com/throneproj/Throne/issues/1267)). اگر برای سایتی که از پروکسی عبور می‌دهید نشانی IP عمومی واقعی شما را نشان دهد، ترافیک UDP پروکسی را دور زده است. این در حالت پروکسی سیستمی رایج است؛ به‌جای آن از حالت TUN استفاده کنید.

## ربایش و دی‌ان‌اس سیستم (حذف‌شده) {#deprecated}

تا نسخهٔ 1.3.2، پنجرهٔ `تنظیمات مسیریابی` (Routing Settings) یک زبانهٔ `ربایش` (Hijack) داشت و Windows یک گزینهٔ `دی‌ان‌اس سیستم` (System DNS) داشت. ربایش (Hijack) یک سرور DNS محلی اجرا می‌کرد که به دامنه‌های انتخاب‌شده با نشانی‌های ثابت پاسخ می‌داد، و `دی‌ان‌اس سیستم` (System DNS) تنظیم DNS در Windows را روی آن سرور می‌گذاشت. هر دو برای برنامه‌هایی بودند که پروکسی سیستمی را نادیده می‌گیرند.

از نسخهٔ 1.4.0، هر دو حذف شده‌اند و Throne تنظیمات قدیمی آن‌ها را نادیده می‌گیرد. به‌جای آن‌ها، برای چنین برنامه‌هایی از `حالتvpn` (Tun Mode) استفاده کنید؛ [حالت TUN](@/guides/tun_mode.fa.md#enable) را ببینید.

## در Android {#android}

Throne برای Android همین تنظیمات DNS را در `تنظیمات` (Settings) ← `DNS` دارد. FakeIP در آنجا `فعال کردن FakeDNS` (Enable FakeDNS) نام دارد. در حالت VPN، Throne همیشه پرس‌وجوهای DNS را درون VPN مدیریت می‌کند. تفاوت‌ها:

- **`localhost` به‌عنوان `DNS مستقیم` (Direct DNS).** از نسخهٔ 2.0.1، این مقدار مستقیماً از سرورهای DNS شبکهٔ Wi-Fi یا شبکهٔ تلفن همراه فعلی می‌پرسد، همانند Windows. حل‌کنندهٔ (resolver) خود Android فقط وقتی به کار می‌رود که شبکه هیچ سرور DNS اعلام نکند. پیش از آن، Throne همیشه از حل‌کنندهٔ Android استفاده می‌کرد که DNS خصوصی (Private DNS) را هم اعمال می‌کند و ممکن بود همهٔ جست‌وجوها را معطل کند. اگر هنگام اتصال، سرورهای DNS شبکه پاسخ ندهند، Throne پیام «اتصال برقرار نشد: DNS شبکه (…) پاسخی نداد. یک DNS مستقیم کارآمد تنظیم کنید.» (Could not connect: the network's DNS (…) did not answer. Set a working Direct DNS.) را نشان می‌دهد. دکمهٔ `DNS` آن، تنظیمات DNS را باز می‌کند.
- **نشانی‌های جعلی IPv6** از نسخهٔ 2.0.2، همانند دسکتاپ، از `2001:db8::/32` می‌آیند.
- **DNS برای هر نمایهٔ مسیریابی** (از نسخهٔ 2.0.4). ویرایشگر نمایهٔ مسیریابی، همانند دسکتاپ، یک کارت `DNS` با `استفاده از تنظیمات DNS سراسری` (Use the global DNS settings) و `استفاده از تنظیمات DNS سفارشی` (Use custom DNS settings) دارد ([DNS برای هر نمایهٔ مسیریابی](#route-dns) را ببینید). تا وقتی نمایهٔ مسیریابی فعال از سرورهای خودش استفاده می‌کند، `تنظیمات` (Settings) ← `DNS` در بالای صفحه این را می‌گوید: تنظیمات آنجا در این حالت فقط برای نمایه‌های مسیریابی دیگر اعمال می‌شوند.
- **یک سرور DNS محلی برای برنامه‌های دیگر.** Throne یک سرور DNS روی `127.0.0.1` اجرا می‌کند که برنامه‌های دیگر دستگاه می‌توانند از آن استفاده کنند. از نسخهٔ 2.0.2، می‌توانید پورت آن را در `تنظیمات` (Settings) ← `ورودی` (Inbound) ← `پورت سرور DNS` (DNS server port) تغییر دهید (پیش‌فرض `5533`).
