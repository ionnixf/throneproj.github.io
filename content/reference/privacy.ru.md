Throne отправляет ваш трафик туда, куда указывают ваши профили и правила маршрутизации. Сам он отправляет только то, что перечислено на этой странице: никакой статистики использования, логов или аварийных дампов.

## HWID и сведения об устройстве {#hwid}

Если включить эту функцию (по умолчанию выключена), Throne отправляет эти заголовки с запросами подписки и никогда — с другими запросами:

- `x-hwid`: `MachineGuid` Windows, аппаратный UUID компьютера Mac или в Linux `/etc/machine-id` (или `/var/lib/dbus/machine-id`; если нет ни того ни другого — случайный идентификатор, который Throne хранит в файле `hwid` в папке конфигурации).
- `x-device-os`: `Windows`, `Linux` или `macOS`.
- `x-ver-os`: версия Windows или macOS либо версия ядра Linux.
- `x-device-model`: модель компьютера (и материнской платы) в Windows, дистрибутив Linux, например `Ubuntu 24.04.1 LTS`, или название и версия macOS.

Включите её в `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Подписка` (Subscription) → `Включить отправку HWID, модели устройства и версии ОС при обновлении подписки` (Enable sending HWID, device model, and OS version when updating subscription) (только в расширенном режиме). Каждый запрос подписки также отправляет User-Agent `Throne/<version>`, если вы не задали другой. Чтобы заменить значения или задать их для отдельной группы, см. [User-Agent и HWID](@/guides/subscriptions.ru.md#user-agent-and-hwid).

**Android:** такой же переключатель находится в `Настройки` → `Подписки` (Subscriptions). Приложение отправляет Android ID (или случайный идентификатор, созданный один раз), `Android`, версию Android и модель устройства. User-Agent по умолчанию — `Throne/Android/<version>`.

## Сетевые запросы {#network-requests}

Запросы с «правилом `Использовать прокси`» (Use proxy) идут напрямую, если не включён `Использовать прокси` (`Настройки` → `Основные настройки` → `Прочее` (Miscellaneous)) или `Системный прокси` (System Proxy): тогда они идут через локальный порт прокси, где решает ваш профиль маршрутизации, и завершаются ошибкой, пока ни один профиль не запущен.

| Запрос | Когда | Куда | Маршрут |
| --- | --- | --- | --- |
| Обновление подписки | Добавление или обновление подписки, вручную или по расписанию | URL вашего провайдера | Правило `Использовать прокси` |
| Удалённый профиль маршрутизации | Добавление или обновление такого профиля, вручную или по расписанию | URL профиля; для `raw.githubusercontent.com` — через `Зеркало наборов правил` (Remote Rule-set Mirror) | Правило `Использовать прокси` |
| Список профилей маршрутизации | `Маршрутизация` (Routing) → `Скачать профили` (Download Profiles) | Репозиторий throneproj/routeprofiles на GitHub, через зеркало | Правило `Использовать прокси` |
| Наборы правил | Профилю нужен набор правил, которого ещё нет в кэше, и примерно раз в день, пока работает профиль | GitHub через `Зеркало наборов правил` (по умолчанию `jsDelivr (Cloudflare)`) или добавленный вами URL `.srs` | Через outbound по умолчанию профиля маршрутизации (напрямую, если это `block`) |
| Определение страны выхода | После каждого запуска профиля (по умолчанию включено) | `Сервис определения IP` (Lookup service); `Автоматически` (Automatic) по очереди пробует `api.ip2location.io`, `ip-api.com`, `ipwho.is`, `ipinfo.io` и `www.cloudflare.com/cdn-cgi/trace` | Всегда через локальный порт прокси |
| Тест задержки (URL test) | Тесты задержки, вручную или автоматически | `URL теста задержки` (Latency Test URL) (по умолчанию `http://cp.cloudflare.com/`) | Через каждый проверяемый профиль |
| Тест IP | Тесты выходного IP | `https://api.ip2location.io/` | Через каждый проверяемый профиль |
| Тест скорости | Тесты скорости | Серверы Speedtest.net или в режиме `Простое скачивание` (Simple Download) — `URL для простого теста скачивания` (Simple Download URL) (по умолчанию `http://cachefly.cachefly.net/1mb.test`) | Через каждый проверяемый профиль |
| Проверка связи | Пока работает автовыбор, и только если задан `URL проверки Direct` (Direct Test URL) или `URL проверки связи` (Connectivity URL) | Этот URL | Напрямую |
| Разрешение доменов | Преобразование доменов ваших серверов в IP | DNS-запросы к вашему серверу `DNS для прямых запросов` (Direct DNS) (по умолчанию системный резолвер) | Напрямую |
| Проверка обновлений | `Проверить наличие обновлений` (Check For Update); скачивание — только после нажатия `Обновить` (Update) | `api.github.com` (релизы и список изменений), затем файл релиза на GitHub | Правило `Использовать прокси` |
| Регистрация WARP | Создание конфигурации или идентификационных данных WARP | `api.cloudflareclient.com` или заданные вами `Домены регистрации…` (Registration Domains…) | Правило `Использовать прокси` |
| Геофайлы Xray | Конфигурации Xray нужны `geoip.dat` или `geosite.dat`, и вы соглашаетесь, или вы нажимаете `Загрузить` (Download) | `URL файла GeoIP` (GeoIP Asset URL) и `URL файла GeoSite` (GeoSite Asset URL) (по умолчанию GitHub) | Правило `Использовать прокси` |
| Сканирование IP | Сканирование в `IP-сканер` (IP Scanner) | TCP-проверка публичных DNS-серверов, например `1.1.1.1:443`, затем сканируемые адреса | Напрямую, даже в режиме TUN |
| Обновление списка IP | Обновление списка IP, источником которого служит URL или набор правил, вручную или по расписанию | URL списка; встроенные списки берутся с GitHub через зеркало | Правило `Использовать прокси` |
| Веб-панель | `Открыть веб-панель` (Open Web dashboard), только в сборках без встроенной панели (в официальных сборках она есть) | GitHub | Всегда через локальный порт прокси |
| Резервные копии WebDAV | Загрузка, восстановление, удаление или проверка; никогда автоматически | Ваши `Server URL` и `Folder`: файл резервной копии и список резервных копий `throne_backups.json` | Правило `Использовать прокси`; с `Connect through the proxy` — всегда через локальный порт прокси |
| NTP | Только если включены `Настройки NTP` (NTP Settings) | Указанный вами NTP-сервер | Выбранный вами `outbound` (по умолчанию `direct`) |

Определение страны выхода отправляет User-Agent Throne: к ip-api.com по обычному HTTP, к остальным сервисам — по HTTPS. С профилем маршрутизации `Default` сервис видит адрес вашего прокси, а не ваш собственный. `Настройки` → `Основные настройки` → `Общие` (Common) → `Определять страну выхода` (Look up exit country) отключает его (в Android — `Настройки` → `Тестирование` (Testing)).

**Резервные копии WebDAV** не шифруются и содержат то, что вы отметили в разделе `Создать резервную копию` (Create Backup), например пароли серверов и ссылки на подписки. Список резервных копий хранит имя устройства, случайный идентификатор устройства, платформу и версию Throne. `Username` и `Password` передаются через базовую аутентификацию HTTP (basic authentication), которую `http://` не шифрует, и никогда не попадают в резервную копию. См. [Резервные копии на WebDAV](@/guides/backup.ru.md#webdav).

Проверка и скачивание обновлений всегда проверяют TLS-сертификат GitHub, даже если включён `Игнорировать ошибки TLS` (Ignore TLS errors).

Запросы от клиента [Throne API](@/advanced/api.ru.md) — это те же запросы с теми же маршрутами. Веб-интерфейс `thronectl` ничего не загружает с других сайтов. [Headless Throne](@/headless/_index.ru.md) не определяет страну выхода и скачивает отсутствующие геофайлы Xray без вопросов.

DNS-запросы для трафика ваших приложений отправляются на серверы из `Настройки маршрутизации` (Routing Settings) → `DNS` или на серверы активного профиля маршрутизации, см. [DNS](@/guides/dns.ru.md).

**Android:**

- Если включён `Настройки` → `Подписки` → `Использовать прокси` (Use proxy) или выбран режим `Только прокси` (Proxy only), собственные запросы приложения идут через локальный прокси, пока работает профиль. Пока ни один профиль не запущен, обновление подписок и регистрация WARP завершаются ошибкой, если включён `Использовать прокси`, а иначе идут напрямую. Проверка обновлений, загрузка профилей маршрутизации и списка наборов правил всегда идут напрямую.
- `Проверять обновления ежедневно` (Check for updates daily) (по умолчанию выключено) раз в день проверяет GitHub.
- Когда конфигурации Xray нужны геофайлы, приложение скачивает их с GitHub без вопросов.
- Резервные копии WebDAV никогда не идут через локальный прокси.

## Локальный порт прокси {#local-proxy}

Пока работает профиль, Throne слушает локальный порт прокси для подключений SOCKS5 и HTTP, по умолчанию `127.0.0.1:2080`. К адресу `127.0.0.1` могут обращаться только программы на вашем компьютере, но любая из них может пользоваться этим портом без пароля. В `Настройки` → `Основные настройки` → `Общие` → `Настройки inbound` (Inbound Settings) значение `::` или `0.0.0.0` в поле `Прослушиваемый адрес` (Listen Address) открывает порт для других устройств, `Включить авторизацию` (Enable Authorization) (по умолчанию выключено) требует `Имя пользователя для inbound` (Inbound Username) и `Пароль для inbound` (Inbound Password), а `Отключить mixed inbound` (Disable Mixed Inbound) отключает порт.

`Разрешить подключаться другим устройствам` (Allow other devices to connect) устанавливает для `Прослушиваемый адрес` значение `::`, и тогда вашим прокси может пользоваться любое устройство, которое может связаться с вашим компьютером. Вместе с ним включите `Включить авторизацию`, см. [Доступ из локальной сети](@/guides/proxy_modes.ru.md#lan-sharing).

| Другой локальный порт | По умолчанию | Кто может к нему обратиться |
| --- | --- | --- |
| `Порт DNS-сервера` (DNS Server Port) | `5533` | Только этот компьютер, если не отметить `Разрешить подключаться другим устройствам` (Allow other devices to connect), см. [DNS-сервер для других устройств](@/guides/dns.ru.md#dns-server). |
| Clash API | Выкл. | Его `Прослушиваемый адрес` (по умолчанию `127.0.0.1`). Задайте `Secret`. |
| API sing-box / веб-панель | Выкл. | Только этот компьютер, со случайным `Secret`. |
| Throne API | Выкл.; порт `9095`, когда включён | Только этот компьютер; если для `Прослушивать` (Listen on) выбрано `Локальная сеть` (Local network), — любое устройство, которое может к нему обратиться, в пределах `Разрешенные адреса` (Allowed addresses). Клиентам нужен ключ, см. [Throne API и thronectl](@/advanced/api.ru.md#security). |

- Когда профиль использует Xray, ядро также открывает внутренние порты на `127.0.0.1`, каждый из которых защищён случайным паролем. Throne и его ядро общаются через локальный сокет, а не через сетевой порт.
- [Headless Throne](@/headless/_index.ru.md) включает Throne API при первом запуске на `127.0.0.1:9095` с ключом в файле, который может читать только его пользователь.
- У веб-интерфейса `thronectl` свой порт, по умолчанию `127.0.0.1:9096`, и он требует пароль, см. [Веб-интерфейс](@/headless/web.ru.md#security).
- **Android:** в `Настройки` → `Входящие` (Inbound) есть `Порт прокси SOCKS5` (Proxy port), `Разрешить подключения из локальной сети` (Allow connections from the LAN) (по умолчанию выключено) и `Включить авторизацию` (Enable authorization). API sing-box по умолчанию включён на `127.0.0.1:9091` со случайным секретом. Throne API нет.

## Этот сайт {#website}

Этот сайт документации подсчитывает посещения с помощью Яндекс Метрики: просмотры страниц, страницу, с которой пришёл посетитель, щелчки по странице и по ссылкам, а также время пребывания на сайте. Запись сеансов отключена. В приложения Throne этот счётчик не входит.
