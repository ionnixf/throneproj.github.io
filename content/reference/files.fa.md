## خط فرمان {#command-line}

| گزینه | کاری که انجام می‌دهد |
| --- | --- |
| `-appdata` | داده‌ها را به‌جای کنار برنامه، در پوشهٔ کاربری شما نگه می‌دارد. [پوشهٔ داده‌ها](#data-folder) را ببینید. |
| `-appdata <folder>` | داده‌ها را در یک پوشهٔ `config` درون `<folder>` نگه می‌دارد. |
| `-tray` | در سینی سیستم و با پنجرهٔ پنهان اجرا می‌شود. |
| یک لینک `throne://` | لینک را طوری پردازش می‌کند که انگار روی آن کلیک کرده‌اید. [لینک‌های عمیق](@/advanced/deeplinks.fa.md) را ببینید. |
| مسیر فایل‌ها یا نشانی‌های `file://` | فایل‌ها را وارد می‌کند، مانند `برنامه` (Program) ← `Add profile from File(s)`. |
| `--headless` | Throne را بدون پنجره، به‌صورت سرویس یا در کانتینر اجرا می‌کند. [Throne بدون رابط گرافیکی](@/headless/_index.fa.md) را ببینید؛ گزینه‌های آن در [خط فرمان و پوشهٔ داده‌ها](@/headless/command_line.fa.md) آمده‌اند. |
| `--check`، `--health`، `--print-connection` | بررسی می‌کنند که آیا این رایانه می‌تواند Throne بدون رابط گرافیکی را اجرا کند، وضعیت نمونهٔ در حال اجرا را از خودش می‌پرسند، یا تنظیمات لازم برای `thronectl` را چاپ می‌کنند. |

```bash
./Throne -appdata "$HOME/throne-test"
```

```powershell
.\Throne.exe -appdata D:\ThroneData
```

- برای هر پوشهٔ داده فقط یک Throne اجرا می‌شود. اجرای دوباره، لینک یا فایل‌ها را به Throne در حال اجرا می‌سپارد و پنجرهٔ آن را به جلو می‌آورد. اگر یک Throne بدون رابط گرافیکی از این پوشه استفاده کند، اجرای جدید پیام «Throne is running in the background» را نشان می‌دهد و خارج می‌شود؛ [عیب‌یابی](@/help/troubleshooting.fa.md#background-throne) را ببینید.
- **macOS:** برای ارسال گزینه‌ها، برنامهٔ درون بستهٔ برنامه (app bundle) را اجرا کنید: `/Applications/Throne.app/Contents/MacOS/Throne -tray`.

## پوشهٔ داده‌ها {#data-folder}

Throne داده‌های شما را در پوشه‌ای به نام `config` نگه می‌دارد. `تنظیمات` (Settings) ← `پوشه Config باز شود` (Open Config Folder) آن را باز می‌کند (فقط در حالت پیشرفته؛ [حالت ساده و پیشرفته](@/get_started/configuration.fa.md#interface-mode) را ببینید).

| روش نصب Throne | پوشهٔ داده‌ها |
| --- | --- |
| فایل ZIP برای Windows یا Linux | `config` در پوشهٔ `Throne` استخراج‌شده (قابل‌حمل) |
| نصب‌کنندهٔ Windows، برای کاربر فعلی (پیش‌فرض) | `config` در پوشهٔ نصب (قابل‌حمل)، که به‌طور پیش‌فرض `%LOCALAPPDATA%\Throne\config` است |
| نصب‌کنندهٔ Windows، برای همهٔ کاربران | `%LOCALAPPDATA%\Throne\config` هر کاربر |
| بستهٔ `.deb` یا `.rpm` یا اسکریپت نصب Linux | `~/.config/Throne/config`، یا اگر `XDG_CONFIG_HOME` را تنظیم کرده باشید، `$XDG_CONFIG_HOME/Throne/config` |
| macOS | `~/Library/Preferences/Throne/config` |

- نسخهٔ قابل‌حمل وقتی با `-appdata` اجرا شود، از پوشهٔ مخصوص کاربر استفاده می‌کند: `%LOCALAPPDATA%\Throne\config` در Windows و `~/.config/Throne/config` در Linux. اگر نتواند در پوشهٔ خودش بنویسد (برای مثال در `Program Files`)، خودبه‌خود به آنجا می‌رود: یک بار پوشهٔ `config` موجود را کپی می‌کند و پس از آن، حتی اگر آن را با دسترسی مدیر (administrator) اجرا کنید، همچنان از پوشهٔ مخصوص کاربر استفاده می‌کند.
- بسته‌هایی از منابع دیگر (WinGet، Scoop، AUR، Nix) ممکن است از پوشه‌های دیگری استفاده کنند. `پوشه Config باز شود` همیشه پوشهٔ درست را نشان می‌دهد.
- فایل‌های geo مربوط به Xray یعنی `geoip.dat` و `geosite.dat`، و پوشهٔ `diagnostics` (از `تنظیمات پایه` (Basic Settings) ← `Diagnostics`) کنار پوشهٔ `config` هستند، نه درون آن.

### فایل‌های پوشهٔ config {#config-files}

| فایل یا پوشه | محتوا |
| --- | --- |
| `throne.db` | نمایه‌ها، گروه‌ها، نمایه‌های مسیریابی، نمایه‌های OTP و تنظیمات (SQLite). تا وقتی Throne در حال اجراست، `throne.db-wal` و `throne.db-shm` کنار آن ظاهر می‌شوند. |
| `throne_stats.db` | تاریخچهٔ ترافیک برای `Tools` → `Traffic Stats`: دقیقه‌به‌دقیقه برای 48 ساعت و ساعتی برای 90 روز. `تنظیمات پایه` ← `استایل` (Style) ← `Disable Traffic Aggregation` آن را متوقف می‌کند. |
| `cache.db` | حافظهٔ نهان (cache) هسته: مجموعه‌قوانینِ دانلودشده، آخرین انتخاب هر انتخابگر خودکار و، اگر `Save Cache To File` روشن باشد، حافظهٔ نهان DNS. |
| `logs/` | فایل‌های گزارش؛ [فایل گزارش](#log-file) را ببینید. |
| `crashes/` | فایل‌های crash dump (فقط Windows). 5 مورد جدیدتر نگه داشته می‌شوند. |
| `icons/` | آیکون‌های سفارشی سینی سیستم برای `تنظیمات پایه` ← `استایل` ← `Enable Custom Icons`: `Off.png`، `Throne.png` (نمایه‌ای در حال اجراست)، `Proxy.png`، `Tun.png` و `Connecting.png`. |
| `hwid` | فقط Linux: شناسهٔ دستگاهی که Throne ساخته است، چون سیستم `/etc/machine-id` یا `/var/lib/dbus/machine-id` قابل‌استفاده‌ای ندارد. [HWID](@/reference/privacy.fa.md#hwid) را ببینید. |
| `.lock` | نشان می‌دهد که یک Throne از این پوشه استفاده می‌کند. Throne هرگز آن را حذف نمی‌کند. |
| `dashboard/` | یک داشبورد وب برای Clash API. صفحهٔ موقت را با فایل‌های داشبورد جایگزین کنید. |
| `sb-dashboard/` | داشبورد وبی که `Tools` → `Open Web dashboard` باز می‌کند. |

برای انتقال داده‌هایتان به رایانهٔ دیگر یا به Android، به‌جای کپی کردن فایل‌ها از یک پشتیبان `.thrbackup` استفاده کنید. [پشتیبان‌گیری و بازیابی](@/guides/backup.fa.md#backup-restore) را ببینید.

## گزارش‌ها {#logs}

زبانهٔ `گزارش‌ها` (Logs) در پایین پنجرهٔ اصلی، پیام‌های Throne و هسته را نشان می‌دهد.

تنظیمات گزارش در `تنظیمات` ← `تنظیمات پایه` ← `Logging` قرار دارند (فقط در حالت پیشرفته):

| تنظیم | پیش‌فرض | کاری که انجام می‌دهد |
| --- | --- | --- |
| `حداکثر خطوط فایل لاگ` (Max log lines) | `500` | تعداد خطوطی که زبانهٔ `گزارش‌ها` نگه می‌دارد. |
| `Sing-box Log level` | `info` | میزان جزئیاتی که هسته می‌نویسد: `trace`، `debug`، `info`، `warn`، `error`، `fatal` یا `panic`. |
| `Xray Log level` | `warning` | میزان جزئیاتی که Xray می‌نویسد: `debug`، `info`، `warning`، `error` یا `none`. |
| `Log Filtering` | خاموش | `Enable Include Rules` فقط خطوطی را نشان می‌دهد که با کلیدواژه‌ها یا عبارت‌های باقاعدهٔ (regular expression) شما منطبق‌اند و `Enable Exclude Rules` آن‌ها را پنهان می‌کند. خطوط پنهان‌شده همچنان در فایل گزارش نوشته می‌شوند. |

برای ثبت یک گزارش دقیق جهت گزارش باگ، مراحل [گزارش باگ](@/help/bug_reports.fa.md#logs) را دنبال کنید.

### فایل گزارش {#log-file}

Throne گزارش‌ها را با جزئیات بیشتر در فایل `logs/throne.log` درون پوشهٔ config هم می‌نویسد.

- Throne در هر بار اجرا یک فایل جدید شروع می‌کند. وقتی حجم فایل به 4 MB برسد، نام آن را به `throne.log.1` تغییر می‌دهد و فایل جدیدی شروع می‌کند؛ حداکثر سه بخش قدیمی (`throne.log.1` تا `throne.log.3`) نگه داشته می‌شوند.
- اگر Throne به‌درستی بسته نشده باشد، گزارش آن نشست با نام `crashed-YYYYMMDD-HHMMSS.log` نگه داشته می‌شود (5 مورد جدیدتر) و در اجرای بعدی، زبانهٔ `گزارش‌ها` هشداری همراه با مسیر پوشهٔ گزارش‌ها نشان می‌دهد.

{% alert_warning() %}
گزارش‌ها ممکن است دامنه‌هایی را که بازدید کرده‌اید و نشانی سرورهای شما را در بر داشته باشند. پیش از انتشار عمومی یک فایل گزارش، آن را بررسی کنید.
{% end %}

**Android:** در منوی کناری `آمار و اطلاعات` (Logs) را باز کنید. `اشتراک‌گذاری گزارش‌ها` (Share logs) و `ذخیره گزارش‌ها…` (Save logs…) از گزارش‌ها خروجی می‌گیرند و داده‌های حساس به‌طور پیش‌فرض در خروجی پنهان می‌شوند. سطح گزارش در `تنظیمات` ← `هسته` (Core) ← `سطح ثبت آمار` (Log level) است (پیش‌فرض: `warn`). [عیب‌یابی Android](@/android/troubleshooting.fa.md#logs) را ببینید.

## بازنشانی Throne {#reset}

Throne دکمهٔ بازنشانی ندارد. برای شروع دوباره با تنظیمات پیش‌فرض، یک پوشهٔ config جدید و خالی به Throne بدهید:

1. اگر می‌خواهید چیزی را نگه دارید، ابتدا یک پشتیبان بسازید: `تنظیمات` ← `تنظیمات پایه` ← `Backup and Restore` → `Create Backup...`.
2. `تنظیمات` ← `پوشه Config باز شود` محل پوشه را نشان می‌دهد.
3. با `خروج` (Exit) در منوی سینی سیستم یا منوی `برنامه` از Throne خارج شوید. بستن پنجره کافی نیست.
4. نام پوشهٔ `config` را تغییر دهید، برای مثال به `config-old`.
5. Throne را اجرا کنید. برنامه یک پوشهٔ `config` جدید با تنظیمات پیش‌فرض می‌سازد.

برای برگرداندن بخشی از داده‌های قدیمی‌تان، از `Restore from Backup...` در همان زبانه استفاده کنید و فقط همان بخش‌ها را انتخاب کنید. برای لغو بازنشانی، از Throne خارج شوید، پوشهٔ `config` جدید را حذف کنید و نام `config-old` را دوباره به `config` برگردانید.

بازنشانی چیزهایی را که بیرون از پوشهٔ config ذخیره شده‌اند تغییر نمی‌دهد: `با سیستم شروع شود` (Start with system) (یک مورد اجرای خودکار در سیستم‌عامل)، ثبت لینک‌های `throne://` و فایل‌های geo مربوط به Xray.

**Windows:** هنگام حذف نسخه‌ای که با نصب‌کننده نصب شده است، برنامه پیشنهاد می‌دهد پوشهٔ config هم حذف شود.

**Android:** `تنظیمات` ← `بازگردانی تنظیمات پیش‌فرض` (Restore default settings) همهٔ تنظیمات را بازنشانی می‌کند، اما نمایه‌ها، گروه‌ها و نمایه‌های مسیریابی شما را نگه می‌دارد و سپس برنامه را دوباره راه‌اندازی می‌کند. برای حذف همه‌چیز، داده‌های برنامه را در تنظیمات برنامه‌های Android پاک کنید. مدیرهای فایل نمی‌توانند داده‌های برنامه را باز کنند؛ پس برای بیرون آوردن آن‌ها از یک پشتیبان `.thrbackup` استفاده کنید.
