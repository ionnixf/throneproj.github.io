Throne ترافیک شما را به همان جایی می‌فرستد که نمایه‌ها و قوانین مسیریابی‌تان تعیین می‌کنند. خودش فقط چیزهایی را ارسال می‌کند که در این صفحه آمده است: نه آمار استفاده، نه گزارش‌ها و نه فایل‌های crash dump.

## HWID و اطلاعات دستگاه {#hwid}

اگر این قابلیت را روشن کنید (به‌طور پیش‌فرض خاموش است)، Throne این هدرها را همراه درخواست‌های اشتراک ارسال می‌کند و هرگز همراه درخواست دیگری نمی‌فرستد:

- `x-hwid`: مقدار `MachineGuid` در Windows، UUID سخت‌افزاری Mac، یا در Linux `/etc/machine-id` (یا `/var/lib/dbus/machine-id`؛ اگر هیچ‌کدام نباشد، یک شناسهٔ تصادفی که Throne در فایل `hwid` در پوشهٔ config نگه می‌دارد).
- `x-device-os`: `Windows`، `Linux` یا `macOS`.
- `x-ver-os`: نسخهٔ Windows یا macOS، یا نسخهٔ کرنل Linux.
- `x-device-model`: مدل رایانه (و مادربورد) در Windows، نام توزیع Linux، برای مثال `Ubuntu 24.04.1 LTS`، یا نام و نسخهٔ macOS.

آن را در `تنظیمات` (Settings) ← `تنظیمات پایه` (Basic Settings) ← `اشتراک` (Subscription) ← `Enable sending HWID, device model, and OS version when updating subscription` روشن کنید (فقط در حالت پیشرفته). هر درخواست اشتراک User-Agent `Throne/<version>` را هم ارسال می‌کند، مگر اینکه User-Agent دیگری تعیین کنید. برای جایگزین کردن مقادیر یا تعیین آن‌ها برای هر گروه، [User-Agent و HWID](@/guides/subscriptions.fa.md#user-agent-and-hwid) را ببینید.

**Android:** همین کلید در `تنظیمات` ← `اشتراک‌ها` (Subscriptions) است. برنامه شناسهٔ Android (یا یک شناسهٔ تصادفی که یک بار ساخته می‌شود)، `Android`، نسخهٔ Android و مدل دستگاه را ارسال می‌کند. User-Agent پیش‌فرض آن `Throne/Android/<version>` است.

## درخواست‌های شبکه {#network-requests}

درخواست‌هایی که با «قانون `Use proxy`» مشخص شده‌اند مستقیم ارسال می‌شوند، مگر اینکه `Use proxy` (`تنظیمات` ← `تنظیمات پایه` ← `Miscellaneous`) یا `پروکسی سیستمی` (System Proxy) روشن باشد: در این صورت از پورت پروکسی محلی عبور می‌کنند، جایی که نمایهٔ مسیریابی شما مسیرشان را تعیین می‌کند، و تا وقتی هیچ نمایه‌ای در حال اجرا نیست ناموفق می‌شوند.

| درخواست | زمان | مقصد | مسیر |
| --- | --- | --- | --- |
| به‌روزرسانی اشتراک | افزودن یا به‌روزرسانی یک اشتراک، دستی یا طبق زمان‌بندی | نشانی ارائه‌دهندهٔ شما | قانون `Use proxy` |
| نمایهٔ مسیریابی راه‌دور | افزودن یا به‌روزرسانی آن، دستی یا طبق زمان‌بندی | نشانی نمایه، که برای `raw.githubusercontent.com` از طریق `Remote Rule-set Mirror` دریافت می‌شود | قانون `Use proxy` |
| فهرست نمایه‌های مسیریابی | `مسیریابی` (Routing) ← `Download Profiles` | مخزن throneproj/routeprofiles در GitHub، از طریق همان mirror | قانون `Use proxy` |
| مجموعه‌قوانین | وقتی نمایه‌ای به مجموعه‌قوانینی نیاز دارد که در حافظهٔ نهان نیست، و تقریباً روزی یک‌بار تا وقتی نمایه‌ای در حال اجراست | GitHub از طریق `Remote Rule-set Mirror` (به‌طور پیش‌فرض `jsDelivr(Cloudflare)`)، یا نشانی `.srs` که خودتان اضافه کرده‌اید | از طریق خروجی پیش‌فرض نمایهٔ مسیریابی (اگر `block` باشد، مستقیم) |
| تشخیص کشور خروجی | پس از هر بار اجرای یک نمایه (به‌طور پیش‌فرض روشن) | `Lookup service`؛ `Automatic` به‌ترتیب `api.ip2location.io`، `ip-api.com`، `ipwho.is`، `ipinfo.io` و `www.cloudflare.com/cdn-cgi/trace` را امتحان می‌کند | همیشه پورت پروکسی محلی |
| تست URL | تست‌های URL دستی یا خودکار | `آدرس تست تاخیر` (Latency Test URL) (به‌طور پیش‌فرض `http://cp.cloudflare.com/`) | از طریق هر نمایهٔ تست‌شده |
| تست IP | تست‌های IP خروجی | `https://api.ip2location.io/` | از طریق هر نمایهٔ تست‌شده |
| تست سرعت | تست‌های سرعت | سرورهای Speedtest.net، یا در حالت `بارگیری ساده` (Simple Download)، `نشانی بارگیری ساده` (Simple Download URL) (به‌طور پیش‌فرض `http://cachefly.cachefly.net/1mb.test`) | از طریق هر نمایهٔ تست‌شده |
| بررسی اتصال | هنگام کار یک انتخابگر خودکار، فقط اگر `Direct Test URL` یا `Connectivity URL` تعیین شده باشد | همان نشانی | مستقیم |
| جست‌وجوی دامنه | تفکیک دامنهٔ سرورهای شما | پرس‌وجوی DNS به سرور `دی ان اس مستقیم` (Direct DNS) شما (به‌طور پیش‌فرض حل‌کنندهٔ DNS سیستم‌عامل) | مستقیم |
| بررسی به‌روزرسانی | `بررسی به‌روزرسانی` (Check For Update)؛ دانلود فقط پس از کلیک روی `به‌روزرسانی` (Update) | `api.github.com` (انتشارها و فهرست تغییرات)، سپس فایل انتشار در GitHub | قانون `Use proxy` |
| ثبت‌نام WARP | تولید یک پیکربندی یا هویت WARP | `api.cloudflareclient.com`، یا دامنه‌هایی که در `Registration Domains…` تعیین کرده‌اید | قانون `Use proxy` |
| فایل‌های geo مربوط به Xray | وقتی یک پیکربندی Xray به `geoip.dat` یا `geosite.dat` نیاز دارد و موافقت می‌کنید، یا روی `Download` کلیک می‌کنید | `GeoIP Asset URL` و `GeoSite Asset URL` (به‌طور پیش‌فرض GitHub) | قانون `Use proxy` |
| اسکن IP | اسکن‌ها در `IP Scanner` | یک بررسی TCP به سرورهای DNS عمومی، مانند `1.1.1.1:443`؛ سپس نشانی‌هایی که اسکن می‌کنید | مستقیم، حتی در حالت TUN |
| به‌روزرسانی فهرست IP | به‌روزرسانی فهرست IP‌ای که منبع آن یک URL یا مجموعه‌قوانین است، دستی یا طبق زمان‌بندی | نشانی فهرست؛ فهرست‌های داخلی از GitHub و از طریق همان mirror دریافت می‌شوند | قانون `Use proxy` |
| داشبورد وب | `Open Web dashboard`، فقط در نسخه‌هایی که داشبورد داخلی ندارند (نسخه‌های رسمی دارند) | GitHub | همیشه پورت پروکسی محلی |
| پشتیبان‌گیری WebDAV | بارگذاری، بازیابی، حذف یا آزمایش؛ هرگز به‌صورت خودکار | `Server URL` و `Folder` شما: فایل پشتیبان و فهرست پشتیبان `throne_backups.json` | قانون `Use proxy`؛ وقتی `Connect through the proxy` روشن باشد، همیشه پورت پروکسی محلی |
| NTP | فقط وقتی `تنظیمات NTP` (NTP Settings) روشن باشد | سرور NTP که وارد می‌کنید | مقدار `outbound` انتخاب‌شده (به‌طور پیش‌فرض `direct`) |

تشخیص کشور خروجی User-Agent برنامه را ارسال می‌کند؛ از ip-api.com با HTTP ساده و از سرویس‌های دیگر با HTTPS پرس‌وجو می‌شود. با نمایهٔ مسیریابی `Default`، سرویس نشانی پروکسی شما را می‌بیند، نه نشانی خودتان را. `تنظیمات` ← `تنظیمات پایه` ← `متداول` (Common) ← `Look up exit country` آن را خاموش می‌کند (در Android: `تنظیمات` ← `آزمایش` (Testing)).

**پشتیبان‌گیری WebDAV** رمزگذاری نمی‌شود و بخش‌هایی را که زیر `Create Backup` تیک خورده‌اند در بر دارد، برای مثال گذرواژه‌های سرورها و لینک‌های اشتراک شما. فهرست پشتیبان نام دستگاه، یک شناسهٔ تصادفی دستگاه، پلتفرم و نسخهٔ Throne را ثبت می‌کند. `Username` و `Password` با احراز هویت پایهٔ HTTP (basic authentication) ارسال می‌شوند که روی `http://` رمزگذاری نمی‌شود، و هرگز در نسخهٔ پشتیبان قرار نمی‌گیرند. [پشتیبان‌گیری در WebDAV](@/guides/backup.fa.md#webdav) را ببینید.

بررسی و دانلود به‌روزرسانی همیشه گواهی TLS سایت GitHub را بررسی می‌کنند، حتی وقتی `Ignore TLS errors` روشن است.

درخواست‌های یک کلاینت [Throne API](@/advanced/api.fa.md) همان درخواست‌های بالا هستند و از همان مسیرها می‌روند. رابط وب `thronectl` چیزی از سایت‌های دیگر بارگیری نمی‌کند. [Throne بدون رابط گرافیکی](@/headless/_index.fa.md) کشور خروجی را تشخیص نمی‌دهد و فایل‌های geo مربوط به Xray را که موجود نیستند، بدون پرسیدن دانلود می‌کند.

پرس‌وجوهای DNS مربوط به ترافیک برنامه‌های شما به سرورهای تعیین‌شده در `تنظیمات مسیریابی` (Routing Settings) ← `دی‌ان‌اس` (DNS)، یا به سرورهای نمایهٔ مسیریابی فعال ارسال می‌شوند؛ [DNS](@/guides/dns.fa.md) را ببینید.

**Android:**

- اگر `تنظیمات` ← `اشتراک‌ها` ← `استفاده از پراکسی` (Use proxy) روشن باشد، یا در حالت `فقط به حالت پراکسی` (Proxy only)، درخواست‌های خود برنامه تا وقتی یک نمایه اجرا می‌شود از پروکسی محلی عبور می‌کنند. تا وقتی هیچ نمایه‌ای اجرا نمی‌شود، اگر `استفاده از پراکسی` روشن باشد، به‌روزرسانی اشتراک‌ها و ثبت‌نام WARP ناموفق می‌شوند و در غیر این صورت مستقیم ارسال می‌شوند. بررسی به‌روزرسانی، دانلود نمایه‌های مسیریابی و فهرست مجموعه‌قوانین همیشه مستقیم ارسال می‌شوند.
- `بررسی روزانه به‌روزرسانی‌ها` (Check for updates daily) (به‌طور پیش‌فرض خاموش) روزی یک‌بار GitHub را بررسی می‌کند.
- وقتی یک پیکربندی Xray به فایل‌های geo نیاز دارد، برنامه آن‌ها را بدون پرسیدن از GitHub دانلود می‌کند.
- پشتیبان‌گیری WebDAV هرگز از پروکسی محلی عبور نمی‌کند.

## پورت پروکسی محلی {#local-proxy}

تا وقتی نمایه‌ای در حال اجراست، Throne روی یک پورت پروکسی محلی برای اتصال‌های SOCKS5 و HTTP گوش می‌دهد، که به‌طور پیش‌فرض `127.0.0.1:2080` است. فقط برنامه‌های روی رایانهٔ خودتان می‌توانند به `127.0.0.1` دسترسی داشته باشند، اما همهٔ آن‌ها بدون گذرواژه می‌توانند از این پورت استفاده کنند. در `تنظیمات` ← `تنظیمات پایه` ← `متداول` (Common) ← `Inbound Settings`، مقدار `::` یا `0.0.0.0` برای `آدرس درحال شنود` (Listen Address) پورت را به روی دستگاه‌های دیگر باز می‌کند، `Enable Authorization` (به‌طور پیش‌فرض خاموش) `Inbound Username` و `Inbound Password` را الزامی می‌کند و `Disable Mixed Inbound` پورت را خاموش می‌کند.

`به دستگاه های دیگر اجازه اتصال دهید` (Allow other devices to connect)، `آدرس درحال شنود` را روی `::` تنظیم می‌کند؛ در این صورت هر دستگاهی که به رایانهٔ شما دسترسی دارد می‌تواند از پروکسی شما استفاده کند. همراه با آن، `Enable Authorization` را روشن کنید؛ [اشتراک‌گذاری در شبکهٔ محلی](@/guides/proxy_modes.fa.md#lan-sharing) را ببینید.

| پورت محلی دیگر | پیش‌فرض | چه کسی به آن دسترسی دارد |
| --- | --- | --- |
| `DNS Server Port` | `5533` | فقط همین رایانه، مگر اینکه `به دستگاه های دیگر اجازه اتصال دهید` (Allow other devices to connect) را تیک بزنید؛ [سرور DNS برای دستگاه‌های دیگر](@/guides/dns.fa.md#dns-server) را ببینید. |
| Clash API | خاموش | `آدرس درحال شنود` آن (به‌طور پیش‌فرض `127.0.0.1`). یک `Secret` تعیین کنید. |
| sing-box API / Dashboard | خاموش | فقط همین رایانه، با یک `Secret` تصادفی. |
| Throne API | خاموش؛ پورت `9095` وقتی روشن است | فقط همین رایانه؛ وقتی `Listen on` روی `Local network` باشد، هر دستگاهی که به آن دسترسی دارد، با محدودیت `Allowed addresses`. کلاینت‌ها به کلید نیاز دارند؛ [Throne API و thronectl](@/advanced/api.fa.md#security) را ببینید. |

- وقتی نمایه‌ای از Xray استفاده می‌کند، هسته پورت‌های داخلی‌ای هم روی `127.0.0.1` باز می‌کند که هر کدام با یک گذرواژهٔ تصادفی محافظت می‌شوند. Throne و هسته‌اش از طریق یک سوکت محلی با هم ارتباط برقرار می‌کنند، نه از طریق یک پورت شبکه.
- [Throne بدون رابط گرافیکی](@/headless/_index.fa.md) در نخستین اجرا Throne API را روی `127.0.0.1:9095` روشن می‌کند، با کلیدی در فایلی که فقط کاربر آن می‌تواند بخواند.
- رابط وب `thronectl` پورت خودش را دارد، به‌طور پیش‌فرض `127.0.0.1:9096`، و گذرواژه می‌خواهد؛ [رابط وب](@/headless/web.fa.md#security) را ببینید.
- **Android:** `تنظیمات` ← `ورودی` (Inbound) گزینه‌های `پورت پراکسی` (Proxy port)، `اجازه اتصال از شبکه محلی` (Allow connections from the LAN) (به‌طور پیش‌فرض خاموش) و `فعال‌سازی مجوز` (Enable authorization) را دارد. sing-box API به‌طور پیش‌فرض روشن است، روی `127.0.0.1:9091` با یک secret تصادفی. Throne API وجود ندارد.

## این وب‌سایت {#website}

این وب‌سایت مستندات، بازدیدها را با Yandex Metrika می‌شمارد: بازدید صفحه‌ها، صفحهٔ ارجاع‌دهنده، کلیک‌ها روی صفحه و روی لینک‌ها، و مدت ماندن بازدیدکنندگان. ضبط نشست (session recording) خاموش است. برنامه‌های Throne این شمارنده را ندارند.
