Параметры приложения для компьютера описаны в разделе [Командная строка](@/reference/files.ru.md#command-line).

## Параметры и переменные {#options}

`Throne --headless --help` выводит список параметров. Параметр имеет приоритет над соответствующей переменной. С юнитом systemd задавайте переменные в `/etc/throne/throne.env`, а параметры — с помощью drop-in-файла (см. [Пакеты для Linux](@/headless/installation.ru.md#linux-packages)).

| Параметр | Переменная | Что делает |
| --- | --- | --- |
| `--headless` | `THRONE_HEADLESS=1` | Запуск без окна. |
| `--data-dir DIR` | `THRONE_DATA_DIR` | [Каталог данных](#data-dir). |
| `--restart-mode MODE` | `THRONE_RESTART_MODE` | `auto` (по умолчанию), `exit` или `exec`. См. [Режимы перезапуска](#restart-modes). |
| `--no-resume` | `THRONE_RESUME=0` | Не запускать последний профиль при запуске. |
| `--no-kill-switch` | `THRONE_KILL_SWITCH=0` | Держать [kill switch](@/advanced/kill_switch.ru.md) выключенным в этом запуске. Профили отклоняются, пока настройка `kill_switch` не будет выключена. Для [восстановления доступа](@/headless/recovery.ru.md#recovery). |
| `--log-format FORMAT` | `THRONE_LOG_FORMAT` | `auto` (по умолчанию), `journal` или `plain`. См. [Логи](@/headless/monitoring.ru.md#logs). |
| `--api-listen LISTEN` | `THRONE_API_LISTEN` | `PORT` (на `127.0.0.1`), `IPv4:PORT`, `[IPv6]:PORT`, `*:PORT` или `off`. По умолчанию: `127.0.0.1:9095` или то, что указано в сохранённых настройках. |
| `--api-key-file FILE` | `THRONE_API_KEY_FILE` | Читать ключ API из этого существующего файла (его создаёт `thronectl keygen -o FILE`). По умолчанию: `config/api.key` в каталоге данных. |
| `--api-admin-lan` | `THRONE_API_ADMIN_LAN=1` | Отвечать на [административные запросы](@/headless/thronectl.ru.md#remote) и из сети. |
| `--api-allow LIST` | `THRONE_API_ALLOW` | Адреса и подсети, которым разрешено пользоваться слушателем не на loopback, через запятую или пробел. Если переменная не задана, разрешены все адреса; пустой список приводит к завершению с кодом 64. |
| `--debug` | | Отладочное логирование. |
| `--service` | | Только Windows: работа под управлением диспетчера служб (Service Control Manager). |
| `--health` | | Спросить работающий Throne [о его состоянии](@/headless/monitoring.ru.md#health). |
| `--print-connection` | | Вывести `THRONE_ADDR` и `THRONE_KEY_FILE` для [thronectl](@/headless/thronectl.ru.md#connect). |
| `--check` | | [Проверить](@/headless/monitoring.ru.md#check), может ли этот компьютер запустить headless Throne. |

- `THRONE_RESUME`, `THRONE_KILL_SWITCH` и `THRONE_API_ADMIN_LAN` принимают `1`, `true`, `yes`, `on`, `0`, `false`, `no` или `off`. Любое другое значение приводит к завершению с кодом 64.
- Параметры и переменные `--api-*` при каждом запуске переопределяют сохранённые настройки API и никогда не сохраняются, поэтому неудачную настройку API всегда можно исправить из командной строки.
- `--health`, `--print-connection` и `--check` работают без `--headless`. Используйте только один из них за раз и никогда вместе с `--service`.
- Ссылки и файлы в командной строке приводят к завершению с кодом 64. Импортируйте их через [`thronectl import`](@/headless/thronectl.ru.md#profiles).

## Каталог данных {#data-dir}

Headless Throne использует первый подходящий вариант из списка:

1. `--data-dir`, затем `THRONE_DATA_DIR`.
2. `STATE_DIRECTORY`, которую systemd задаёт для `StateDirectory=`.
3. От root: `/var/lib/throne` в Linux, `/Library/Application Support/Throne` в macOS. В Windows в службе или от LocalSystem: `C:\ProgramData\Throne`.
4. Папка приложения для компьютера: `~/.config/Throne` в Linux, `~/Library/Preferences/Throne` в macOS, `%LOCALAPPDATA%\Throne` в Windows.

Папку портативной установки рядом с программой он никогда не использует; передайте эту папку в `--data-dir`.

В Linux и macOS Throne создаёт недостающие каталоги, доступные для чтения только его пользователю. При запуске от root он отказывается использовать каталог данных, в который могут записывать другие пользователи (код 78), потому что в настройках указаны программы, которые запускает Throne. О Windows см. [Папка данных](@/headless/installation.ru.md#windows-data-folder).

| Путь | Содержимое |
| --- | --- |
| `config/throne.db` | Профили, группы, профили маршрутизации и настройки, как в приложении для компьютера |
| `config/api.key` | Ключ API, доступный для чтения только пользователю Throne |
| `config/logs/throne.log` | Лог текущего запуска. В `crashed-<time>.log` сохраняется лог запуска, который завершился некорректно. |
| `config/crashes/` | Отчёты о сбоях |
| `config/hwid` | [Идентификатор устройства](@/headless/_index.ru.md#device-id), если в системе его нет |
| `web/` | Только в образе Docker: хеш пароля и сертификат TLS [веб-интерфейса](@/headless/web.ru.md#docker) |

## Режимы перезапуска {#restart-modes}

`thronectl restart`, восстановление резервной копии и `SIGHUP` перезапускают Throne. Как именно, определяет `--restart-mode`:

| Режим | Что происходит |
| --- | --- |
| `exit` | Throne завершается с кодом 75, и менеджер служб запускает его снова. |
| `exec` | Throne перезапускается в том же процессе (Linux, macOS). В Windows он запускает новый процесс Throne и завершается с кодом 0. |
| `auto` | `exit` под systemd, launchd или init контейнера либо в службе Windows. `exec` в остальных случаях, например в терминале. |

Поставляемые юниты, plist и образ Docker требуют `auto` или `exit`; служба Windows всегда использует `exit`. `Throne --check` показывает, что выбирает `auto`. В терминале закрытие терминала останавливает Throne с кодом 0, а не перезапускает его.

## Коды завершения {#exit-codes}

Перед завершением Throne записывает в лог `EXIT <code>: <reason>`.

| Код | Значение |
| --- | --- |
| 0 | Остановка: `SIGTERM`, `SIGINT`, `thronectl shutdown`, остановка службы Windows или `Ctrl+C` |
| 1 | Запуск не удался по причине, которая может исчезнуть: блокировка, база данных, IPC-слушатель ядра или адрес `--api-listen`, который не появился в течение 30 секунд |
| 3 | Каталог данных использует другой Throne |
| 64 | Неверный параметр, значение параметра или переменная |
| 70 | Ядро постоянно падало или было непригодно к работе в течение 60 секунд |
| 71 | Профиль подключался 180 секунд или останавливался 90 секунд |
| 75 | Запрошен перезапуск в режиме `exit` или в службе Windows |
| 78 | Ошибка конфигурации: каталог данных (небезопасные права или нет `HOME`, чтобы его найти), файл ключа API, слушатель `--api-listen` или файл базы данных, который нельзя использовать |

Что делают поставляемые файлы служб:

- **Юнит systemd:** через 3 секунды снова запускает Throne после кодов 1, 70, 71 и 75 и оставляет его остановленным после 0, 3, 64 и 78. У него нет ограничения на число запусков (`StartLimitIntervalSec=0`): каждый перезапуск, восстановление и `SIGHUP` — это новый запуск, и ограничение оставило бы Throne остановленным без API.
- **Docker** (`restart: unless-stopped`): запускает его снова после любого завершения, кроме `docker stop`.
- **plist launchd:** запускает его снова после любого кода, кроме 0, не чаще чем раз в 10 секунд, поэтому повторяет и 3, 64 и 78.
- **Служба Windows:** после любого кода, кроме 0, выполняет свои [действия восстановления](@/headless/installation.ru.md#windows).

После трёх запусков подряд без работающего ядра Throne не завершается с кодами 70 и 71, а [остаётся запущенным](@/headless/recovery.ru.md#protection). Если код 78 вызван базой данных, лог сообщает, что делать: переместите повреждённый `config/throne.db` в другое место вместе с его файлами `-wal` и `-shm` или верните резервную копию файла. Файлы только для чтения сделайте доступными для записи пользователю Throne.

У команд проверки свои коды, а при неверном параметре они завершаются с кодом 64:

| Команда | 0 | 1 | 2 |
| --- | --- | --- | --- |
| `--health` | Исправен | Неисправен или ещё запускается | Ни один Throne не ответил, или командная строка Windows запущена без повышенных прав |
| `--check` | Нет строк `[FAIL]` | Есть строка `[FAIL]` | |
| `--print-connection` | Выведены обе строки | | API выключен или не слушает, его ключ хранится не в файле, или командная строка Windows запущена без повышенных прав |

`--health` и `--print-connection` завершаются с кодом 78, если не находят каталог данных (нет `HOME`); укажите его через `--data-dir`.
