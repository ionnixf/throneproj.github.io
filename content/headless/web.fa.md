`thronectl web` یک رابط وب برای Throne بدون رابط گرافیکی، و برای Throne دسکتاپی که [Throne API](@/advanced/api.fa.md) در آن روشن است، ارائه می‌دهد. این یک وب‌سرور کوچک، یعنی دروازه (gateway)، و بخشی از `thronectl` است: از طریق API و با همان نشانی و کلیدی که فرمان‌های دیگر `thronectl` به کار می‌برند با Throne صحبت می‌کند.

## شروع سریع {#quick-start}

دروازه را روی همان دستگاه Throne اجرا کنید، جایی که Throne به همهٔ درخواست‌های آن، از جمله [درخواست‌های مدیریتی](@/headless/thronectl.fa.md#remote)، پاسخ می‌دهد.

### Docker {#docker}

ایمیج Docker وقتی `THRONE_WEB_LISTEN` تنظیم شده باشد، دروازه را در همان کانتینر اجرا می‌کند. در فایل [`compose.yaml`](https://github.com/throneproj/Throne/blob/dev/docker/compose.yaml)، این را به سرویس `throne` اضافه کنید:

```yaml
services:
  throne:
    environment:
      THRONE_WEB_LISTEN: "*:9096"
    ports: ["2080:2080", "9096:9096"]
```

روی میزبانی که از اینترنت قابل دسترسی است، فقط نشانی LAN را منتشر کنید، برای مثال `"192.168.1.2:9096:9096"`. با `docker run`، `-e THRONE_WEB_LISTEN='*:9096' -p 9096:9096` را اضافه کنید.

```bash
docker compose up -d
docker compose logs throne
```

گزارش، گذرواژه و اثر انگشت گواهی را نشان می‌دهد. `https://<host>:9096/` را باز کنید، [اثر انگشت را بررسی کنید](#lan) و وارد شوید.

دروازه وضعیت خود را در `/var/lib/throne/web` روی volume داده‌ها نگه می‌دارد. 3 ثانیه پس از خروج دوباره شروع می‌شود، بنابراین یک [گزینهٔ](#options) نادرست `THRONE_WEB_*` در گزارش تکرار می‌شود.

### بسته‌های Linux (systemd) {#systemd}

بسته‌های `.deb` و `.rpm`، `throne-web.service` را نصب می‌کنند که `thronectl web` را در کنار `throne.service` با یک کاربر پویا (dynamic user) مخصوص خودش اجرا می‌کند، با کلید Throne به‌عنوان یک credential و وضعیتش در `/var/lib/throne-web`:

```bash
sudo systemctl enable --now throne-web
sudo journalctl -u throne-web | grep 'web UI password'
```

روی `127.0.0.1:9096` گوش می‌دهد: آن را از طریق یک [تونل SSH](#ssh-tunnel) باز کنید. برای تغییر گزینه‌هایش، آن‌ها را در `/etc/throne/web.env` از حالت توضیح خارج کنید و `sudo systemctl restart throne-web` را اجرا کنید؛ ارتقاها تغییرات شما را نگه می‌دارند. هرگز کلید یا گذرواژه را در این فایل نگذارید.

- کاربر یونیت نمی‌تواند فایل‌هایی را بخواند که فقط root می‌تواند بخواند، مانند کلید TLS یا فایل گذرواژه. آن‌ها را با `LoadCredential=` بدهید (`sudo systemctl edit throne-web`)، همان‌طور که `/etc/throne/web.env` نشان می‌دهد.
- پورتی پایین‌تر از 1024 به `CAP_NET_BIND_SERVICE` در `AmbientCapabilities=` و `CapabilityBoundingSet=` نیاز دارد.

### به‌صورت دستی، روی هر سیستمی {#manual}

روی دستگاه Throne، [thronectl را به Throne متصل کنید](@/headless/thronectl.fa.md#connect) و دروازه را شروع کنید:

```bash
export THRONE_KEY_FILE=~/.config/throne/api-key
thronectl web
```

دروازه گذرواژه را یک بار چاپ می‌کند و تا وقتی `Ctrl+C` را بزنید، `http://127.0.0.1:9096/` را ارائه می‌دهد. برای Throne دسکتاپ، ابتدا [API را روشن کنید](@/advanced/api.fa.md#enable) و [thronectl را متصل کنید](@/advanced/api.fa.md#connect).

## دسترسی از دستگاه دیگر {#remote}

دروازه روی `127.0.0.1:9096` گوش می‌دهد که فقط دستگاه Throne به آن می‌رسد.

### تونل SSH {#ssh-tunnel}

```bash
ssh -L 9096:127.0.0.1:9096 user@host
```

تا وقتی نشست باز است، `http://localhost:9096/` را روی رایانهٔ خودتان باز کنید (برای Docker، `https://`). اگر پورت 9096 آنجا در حال استفاده است، پورت محلی دیگری به کار ببرید، برای مثال `-L 19096:127.0.0.1:9096`.

### شبکهٔ محلی (HTTPS) {#lan}

```bash
thronectl web --listen '*:9096'
```

`*:9096` روی همهٔ نشانی‌های دستگاه گوش می‌دهد و `192.168.1.2:9096` فقط روی یکی. روی یک نشانی شبکه، دروازه با HTTPS ارائه می‌شود. اگر به آن گواهی ندهید، یک گواهی خودامضا می‌سازد و در هر بار شروع، اثر انگشت SHA-256 آن را چاپ می‌کند؛ صفحهٔ `System` هم آن را نشان می‌دهد. مرورگر هشدار می‌دهد که گواهی قابل اعتماد نیست: جزئیات گواهی را باز کنید و فقط اگر اثر انگشت SHA-256 آن با اثر انگشت چاپ‌شده یکسان بود آن را بپذیرید. اگر فرق داشتند، چیزی میان شما و دستگاه اتصال را رهگیری می‌کند: وارد نشوید.

پورت 9096 را در فایروال دستگاه، و فقط برای شبکهٔ خودتان، باز کنید.

- گواهی برای `localhost`، نام میزبان و نشانی‌هایی صادر می‌شود که دستگاه در آن زمان داشت، و 10 سال اعتبار دارد. برای گواهی جدید، برای مثال پس از تغییر نشانی، پوشهٔ `tls` را در پوشهٔ وضعیت (state directory) حذف کنید و دروازه را دوباره راه‌اندازی کنید.
- برای استفاده از گواهی خودتان، زنجیرهٔ گواهی و کلید خصوصی را به‌صورت فایل‌های PEM با `--tls-cert` و `--tls-key` بدهید. پس از تمدید آن‌ها، دروازه را دوباره راه‌اندازی کنید.

### پشت پروکسی معکوس {#reverse-proxy}

دروازه را روی loopback نگه دارید و نام میزبان خود را به آن بدهید:

```bash
thronectl web --allow-host throne.example.com
```

اگر پروکسی روی دستگاه یا کانتینر دیگری اجرا می‌شود، دروازه باید با `--tls off` روی یک نشانی شبکه گوش دهد. فقط به پروکسی اجازهٔ رسیدن به آن را بدهید: گذرواژه بدون رمزگذاری از آن عبور می‌کند. پروکسی باید:

- **هدر `Host` را بدون تغییر عبور دهد**، وگرنه تغییرات با `403 csrf` شکست می‌خورند. nginx این هدر را عوض می‌کند، مگر اینکه آن را تنظیم کنید؛ Caddy آن را نگه می‌دارد.
- **بدنهٔ درخواست‌ها را تا 512 MiB بپذیرد**، یعنی بزرگ‌ترین پشتیبانی که رابط وب بازیابی می‌کند. nginx فقط 1 MiB می‌پذیرد، مگر اینکه `client_max_body_size` را تنظیم کنید.
- **پاسخ‌ها را بافر نکند**: به‌روزرسانی‌های زنده و گزارش به‌صورت جریان (stream) می‌آیند. هدر `X-Accel-Buffering: no` دروازه، بافر کردن را در nginx خاموش می‌کند.

nginx:

```nginx
server {
    listen 443 ssl;
    server_name throne.example.com;
    ssl_certificate     /etc/ssl/certs/throne.example.com.pem;
    ssl_certificate_key /etc/ssl/private/throne.example.com.key;

    location / {
        proxy_pass http://127.0.0.1:9096;
        proxy_set_header Host $http_host;
        client_max_body_size 512m;
    }
}
```

Caddy:

```text
throne.example.com {
    reverse_proxy 127.0.0.1:9096
}
```

پشت پروکسی، همهٔ مرورگرها از نشانی پروکسی می‌آیند، بنابراین ورودهای ناموفق از یک مرورگر، [دسترسی](#security) بقیه را هم قطع می‌کند.

## گذرواژه {#password}

رابط وب یک گذرواژه دارد و حساب کاربری ندارد. دروازه در نخستین شروع، یک گذرواژهٔ تصادفی می‌سازد، هش آن را در فایل `password` در پوشهٔ وضعیت خود ذخیره می‌کند و گذرواژه را یک بار چاپ می‌کند: در `docker compose logs throne`، در `sudo journalctl -u throne-web | grep 'web UI password'`، یا در ترمینالی که `thronectl web` را در آن شروع کردید.

این خط در آن گزارش می‌ماند، که root، گروه‌های `adm` و `systemd-journal` و هر کسی که اجازهٔ اجرای `docker` را دارد می‌توانند آن را بخوانند. پس از نخستین ورود گذرواژه را تغییر دهید: در صفحهٔ `System`، یا با `thronectl web passwd` که با کاربر دروازه و با همان پوشهٔ وضعیت اجرا شود. گذرواژه دست‌کم 8 نویسه لازم دارد، و تغییر آن همهٔ دیگران را از حساب خارج می‌کند.

```bash
docker compose exec throne thronectl web passwd              # Docker
sudo thronectl web passwd --state-dir /var/lib/throne-web    # systemd unit
```

**گذرواژهٔ فراموش‌شده.** با `thronectl web passwd` یک گذرواژهٔ جدید بگذارید، یا فایل `password` را حذف کنید و دروازه را دوباره راه‌اندازی کنید تا گذرواژهٔ جدیدی چاپ کند.

**فایل گذرواژه.** `--password-file FILE` (`THRONE_WEB_PASSWORD_FILE`) گذرواژه را به‌جای هش ذخیره‌شده، به‌صورت متن ساده از یک فایل می‌خواند، برای مثال از یک Docker secret در `/run/secrets/`. دروازه هر 5 ثانیه فایل را دوباره می‌خواند و وقتی تغییر کند همه را از حساب خارج می‌کند. برای تغییر گذرواژه، خود فایل را تغییر دهید.

**نشست‌ها.** یک ورود تا وقتی معتبر است که مرورگر 12 ساعت بی‌کار نمانده باشد، و حداکثر 7 روز. راه‌اندازی دوبارهٔ دروازه همه را از حساب خارج می‌کند. دروازه حداکثر 64 نشست نگه می‌دارد؛ یک ورود بیشتر، نشستی را پایان می‌دهد که زمان بیشتری از آخرین استفاده‌اش گذشته است.

## رابط وب چه چیزهایی را پوشش می‌دهد {#features}

| صفحه | کارهایی که می‌توانید انجام دهید |
| --- | --- |
| `Status` | وضعیت، نمایهٔ در حال اجرا و سرعت؛ اتصال و قطع اتصال؛ TUN و پروکسی سیستم (فقط در Throne دسکتاپ)؛ نمایهٔ مسیریابی؛ تست‌های در حال اجرا. |
| `Profiles` | مرور، فیلتر، تست، اتصال، ویرایش و حذف نمایه‌ها، یا اتصال بهترین نمایهٔ یک گروه. وارد کردن لینک‌های اشتراک‌گذاری، یک فایل یا یک URL. افزودن، به‌روزرسانی و حذف گروه‌ها و اشتراک‌ها. |
| `Routing` | افزودن، ویرایش و حذف نمایه‌های مسیریابی. روشن و خاموش کردن WARP، انتخاب حالت آن و ثبت آن (که شرایط WARP شرکت Cloudflare را می‌پذیرد). |
| `Traffic` | سرعت، و مجموع ترافیک بر اساس نمایه یا برنامه برای 24 ساعت، 7 روز یا 30 روز. |
| `Connections` | اتصال‌های باز و بسته‌شده، با پردازه، مقصد، خروجی (outbound) و قانون؛ بستن یکی یا همه. |
| `Logs` | گزارش Throne همان‌طور که نوشته می‌شود؛ صفحه جدیدترین 5000 خط را نگه می‌دارد. |
| `Settings` | تنظیماتی که API مدیریت می‌کند، فایل‌های geo، و مجموعه‌قوانین نمایهٔ در حال اجرا. |
| `Backup` | دانلود یک پشتیبان، یا بارگذاری یکی و بازیابی بخش‌هایی که انتخاب می‌کنید. |
| `System` | نسخه‌ها، اینکه دروازه دسترسی مدیریتی دارد یا نه، اثر انگشت گواهی، گذرواژه، خروج از حساب، راه‌اندازی دوباره و خاموش کردن Throne. |

تغییراتی که در پنجرهٔ Throne، با `thronectl` یا با به‌روزرسانی یک اشتراک انجام می‌شوند، ظرف چند ثانیه دیده می‌شوند.

### آنچه در دسکتاپ می‌ماند {#desktop-only}

رابط وب این‌ها را ویرایش نمی‌کند:

- حساب‌های OTP،
- نمایهٔ مسیریابی خودِ یک گروه (برای یک اشتراک جدید، [`thronectl sub add`](@/headless/thronectl.fa.md#profiles) آن را تنظیم می‌کند)،
- نقاط پایانی (endpoints) OpenVPN و OpenConnect یک نمایهٔ مسیریابی،
- نمایه‌های هستهٔ اضافی (Extra Core)، و نمایه‌هایی با تنظیماتی که فقط پنجرهٔ Throne می‌تواند تنظیم کند، مانند پیوند به یک حساب OTP،
- تنظیماتی که API مدیریت نمی‌کند.

این‌ها را در یک Throne دسکتاپ تنظیم کنید و [با یک پشتیبان منتقل کنید](@/headless/thronectl.fa.md#from-desktop)، که در صفحهٔ `Backup` یا با `thronectl backup restore` بازیابی می‌شود. پشتیبان‌هایی که نمایهٔ هستهٔ اضافی دارند رد می‌شوند.

## گزینه‌ها {#options}

پرچم (flag) بر متغیر خودش مقدم است.

| پرچم | متغیر | پیش‌فرض و معنا |
| --- | --- | --- |
| `--listen ADDR` | `THRONE_WEB_LISTEN` | `127.0.0.1:9096`. `PORT` (روی `127.0.0.1`)، `IP:PORT`، `[IPv6]:PORT` و `*:PORT` (همهٔ نشانی‌ها) را می‌پذیرد، اما نام میزبان را نه. |
| `--state-dir DIR` | `THRONE_WEB_STATE_DIR` | هش گذرواژه و گواهی خودامضا. پیش‌فرض: `$STATE_DIRECTORY` از systemd، وگرنه `~/.config/thronectl/web` در Linux، `~/Library/Application Support/thronectl/web` در macOS، `%AppData%\thronectl\web` در Windows. |
| `--tls auto\|on\|off` | `THRONE_WEB_TLS` | `auto` (پیش‌فرض): HTTPS روی نشانی شبکه، HTTP ساده روی loopback. `on`: HTTPS روی loopback هم. `off`: HTTP ساده؛ روی نشانی شبکه فقط پشت یک پروکسی معکوس با TLS. |
| `--tls-cert FILE`، `--tls-key FILE` | `THRONE_WEB_TLS_CERT`، `THRONE_WEB_TLS_KEY` | زنجیرهٔ گواهی و کلید خصوصی خودتان در قالب PEM، به‌جای گواهی خودامضا. با `auto`، روی loopback هم HTTPS را روشن می‌کنند. |
| `--allow-host LIST` | `THRONE_WEB_ALLOW_HOST` | نام‌های میزبان دیگری که مرورگرها می‌توانند به کار ببرند، مانند نام یک پروکسی معکوس، جداشده با ویرگول یا فاصله. دروازه برای مقابله با DNS rebinding به نام‌های دیگر با `421 Misdirected Request` پاسخ می‌دهد: روی loopback فقط همین نام‌ها، `localhost`، `127.0.0.1` و `::1` را می‌پذیرد؛ روی نشانی شبکه هر نامی را، مگر اینکه این گزینه تنظیم شده باشد. |
| `--password-file FILE` | `THRONE_WEB_PASSWORD_FILE` | گذرواژه به‌صورت متن ساده، به‌جای هش ذخیره‌شده. [گذرواژه](#password) را ببینید. |

دروازه Throne را همان‌طور پیدا می‌کند که هر فرمان `thronectl`، و زیر systemd کلید را از credential به نام `api.key` هم می‌خواند. `thronectl web` وقتی با `Ctrl+C` یا `SIGTERM` متوقف شود با کد 0 خارج می‌شود؛ با کد 2 برای گزینه یا متغیر نادرست، نبود کلید، فایل گذرواژه یا فایل `password` معیوب، یا گواهی‌ای که بارگذاری نمی‌شود؛ و با کد 3 وقتی نمی‌تواند گوش دهد یا برای خطای دیگری.

## امنیت {#security}

- **رابط وب یک کلاینت مدیریتی است.** هر کسی که وارد شود می‌تواند همان کارهایی را بکند که `thronectl` می‌کند، از جمله دانلود پشتیبان‌ها که اطلاعات ورود نمایه‌ها و رمزهای OTP شما را به‌صورت متن ساده دارند، و خاموش کردن Throne. گذرواژه را فقط به کسانی بدهید که اجازهٔ مدیریت Throne را دارند.
- **کلید API نزد دروازه می‌ماند.** مرورگر فقط یک کوکی نشست و یک توکن نشست می‌گیرد.
- **محدودیت‌های ورود.** پس از 5 ورود ناموفق در 5 دقیقه از یک نشانی (برای IPv6، از یک شبکهٔ ‎/64)، دروازه ورود از آن نشانی را به مدت 60 ثانیه رد می‌کند، و پس از هر شکست بعدی دو برابر بیشتر، تا حداکثر 15 دقیقه. وقتی در مجموع بیش از 30 ورود در یک دقیقه ناموفق باشد، هر ورودی را تا پایان آن دقیقه رد می‌کند.
- **loopback و تونل SSH را ترجیح دهید.** روی شبکه از HTTPS استفاده کنید و اثر انگشت گواهی را بررسی کنید، یا از گواهی‌ای استفاده کنید که مرورگرها به آن اعتماد دارند. HTTP ساده روی یک نشانی شبکه، گذرواژه و نشست را بدون رمزگذاری می‌فرستد.
- **دروازه را روی دستگاه Throne اجرا کنید**، تا API در Throne بتواند روی loopback بماند.

## عیب‌یابی {#troubleshooting}

| نشانه | علت و راه‌حل |
| --- | --- |
| `Throne is not reachable. Retrying…` (`throne_unreachable`) | Throne اجرا نمی‌شود، API آن خاموش است، یا دروازه نشانی نادرستی دارد. `thronectl status` را با تنظیمات دروازه اجرا کنید. |
| `Throne refuses the web UI` یا `Throne refused the connection` (`throne_rejected`) | کلید دروازه نادرست است. کلید فعلی Throne (`config/api.key` در پوشهٔ داده‌ها) را به آن بدهید و دوباره راه‌اندازی‌اش کنید. از دستگاه دیگر، 5 تلاش ناموفق از نشانی آن، حتی از سوی کلاینت دیگری با کلید قدیمی، آن را 60 ثانیه مسدود می‌کند. |
| `The web UI's connection to Throne lacks admin rights` (`forbidden`) | دروازه روی دستگاه Throne اجرا نمی‌شود. آن را آنجا اجرا کنید، یا اجازه دهید Throne از شبکه به درخواست‌های مدیریتی پاسخ دهد: `--api-admin-lan` برای Throne بدون رابط گرافیکی، `اجازهٔ مدیریت از شبکهٔ محلی` (Allow management from the local network) در برنامهٔ دسکتاپ. |
| `421 Misdirected Request: this host name is not accepted` | دروازه را با `localhost` یا یک نشانی IP باز کنید، یا نام را با [`--allow-host`](#options) اضافه کنید. |
| پشت پروکسی معکوس، ورود شکست می‌خورد: `The web UI server refused the request because it came from another origin` (`403 csrf`) | پروکسی هدر `Host` را تغییر می‌دهد: [پشت پروکسی معکوس](#reverse-proxy) را ببینید. |
| `Too many failed attempts. Try again in … s.` (`rate_limited`) | صبر کنید تا شمارش معکوس تمام شود. |
| `thronectl web` خارج می‌شود: `address already in use; --listen picks another address` | برنامهٔ دیگری، یا یک `thronectl web` دیگر، پورت 9096 را گرفته است. آن را متوقف کنید، یا `--listen` دیگری بدهید. |
| بازیابی پشتیبان از طریق nginx با `413` شکست می‌خورد | `client_max_body_size 512m;` را تنظیم کنید. |
| `The password comes from a password file` | فایلی را که `--password-file` نام می‌برد تغییر دهید. |
