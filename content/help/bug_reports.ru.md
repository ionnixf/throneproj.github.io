Сообщайте об ошибках на GitHub:

- Throne для компьютера: [github.com/throneproj/Throne/issues](https://github.com/throneproj/Throne/issues)
- Throne для Android: [github.com/throneproj/ThroneForAndroid/issues](https://github.com/throneproj/ThroneForAndroid/issues)

С вопросами о том, как пользоваться Throne для компьютера, обращайтесь не в issue, а в [категорию Q&A на GitHub Discussions](https://github.com/throneproj/Throne/discussions/categories/q-a).

{% alert_warning() %}
Все issue публичны. Перед публикацией удалите из логов, снимков экрана и конфигураций URL подписок, токены, пароли, UUID, закрытые ключи и адреса серверов. Throne для компьютера не удаляет их за вас, а при неудачном обновлении подписки в лог записывается полный URL подписки. Если вы по ошибке опубликовали секретные данные, попросите провайдера их сбросить.
{% end %}

## Перед отправкой {#before}

1. Обновите Throne через `Программа` (Program) → `Проверить наличие обновлений` (Check For Update) или со [страницы загрузок](@/downloads.ru.md).
2. Поищите своё сообщение об ошибке среди открытых и закрытых issue и прочитайте [FAQ](@/help/faq.ru.md) и [Устранение неполадок](@/help/troubleshooting.ru.md).
3. Проверьте проблему на [чистой конфигурации](@/reference/files.ru.md#reset), в которой есть только то, что нужно, чтобы её показать, и укажите в отчёте, возникает ли она и там.
4. Если вы пользуетесь пакетом из WinGet, Scoop, AUR или Nix, проверьте также официальную сборку: разработчики не поддерживают эти пакеты.
5. Если не работает только один сервер, проверьте его в другом приложении. Если он не работает и там, обратитесь к своему провайдеру.

## Сбор логов {#logs}

### Версия для компьютера {#desktop-logs}

Вкладка `Логи` (Logs) внизу главного окна показывает лог, а Throne записывает те же строки в `logs/throne.log` в папке конфигурации (`Настройки` (Settings) → `Открыть папку конфигурации` (Open Config Folder)). Файл начинается заново при каждом запуске Throne, поэтому скопируйте его до перезапуска.

Чтобы записать подробный лог:

1. В `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Логирование` (Logging) (только в расширенном режиме, см. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode)) установите для `Уровень логирования Sing-box` (Sing-box Log level) значение `debug`, а для профилей Xray — также для `Уровень логирования Xray` (Xray Log level).
2. Увеличьте `Макс. кол-во строк в логах` (Max log lines), например до `2000`, чтобы Throne не отбрасывал строки лога.
3. Нажмите `ОК` (OK) и перезапустите Throne через `Программа` (Program) → `Перезапустить программу` (Restart Program).
4. Воспроизведите проблему и приложите `logs/throne.log`. Если вместо этого вы копируете текст с вкладки `Логи`, сначала закройте её строку фильтра.
5. Верните уровни логирования к `info` (sing-box) и `warning` (Xray).

После сбоя приложите `logs/crashed-<date>-<time>.log`, а в Windows — файлы `.txt` и `.dmp` из папки `crashes`.

### Android {#android-logs}

Откройте боковое меню и нажмите `Журналы` (Logs). Оставьте включённым `Скрывать конфиденциальные данные` (Hide sensitive data) (так по умолчанию), затем нажмите `Поделиться журналом` (Share logs) или `Сохранить журнал…` (Save logs…). Для подробного лога сначала установите для `Настройки` (Settings) → `Ядро` (Core) → `Тип журнала` (Log level) значение `debug` (а для профилей Xray — также `Уровень журнала Xray` (Xray log level)). См. [Устранение неполадок на Android](@/android/troubleshooting.ru.md#logs).

## Диагностика {#diagnostics}

Если Throne зависает, перестаёт отвечать или сильно нагружает процессор, разработчики могут попросить файл диагностики (Diagnostics) — 30-секундную запись того, что делает ядро.

1. Приведите Throne в состояние, в котором проявляется проблема, например дождитесь зависания. Не перезапускайте Throne.
2. В `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Диагностика` (Diagnostics) отметьте параметры, о которых попросил разработчик: `Конфликт блокировок (Lock contention)`, `Трассировка выполнения (файл большего размера)` (Execution trace (larger file)) или `Добавить логи Throne` (Include Throne logs).
3. Нажмите `Запустить` (Start) и подождите 30 секунд. `Запустить` работает, только пока запущено ядро.
4. Нажмите `Показать в папке` (Show in folder) и приложите файл `throne-profile-<date>-<time>.zip`.

В файле указаны версия Throne, система и несколько настроек, но нет ваших конфигураций. `Добавить логи Throne` добавляет ваши логи, в которых есть посещённые домены и адреса серверов. На Android используйте `Настройки` (Settings) → `Диагностика` (Diagnostics); см. [Диагностика](@/android/troubleshooting.ru.md#diagnostics).

## Что указать {#what-to-include}

Используйте шаблон issue и заполните все поля:

| Пункт | Где найти |
| --- | --- |
| Версия Throne | `Программа` (Program) → `О программе` (About), где можно скопировать версии всех компонентов. На Android: `О приложении` (About). |
| Способ установки | ZIP, установщик Windows, `.deb`, `.rpm`, установочный скрипт, репозиторий или менеджер пакетов, а также пользуетесь ли вы [headless Throne](@/headless/_index.ru.md). |
| Режим | `Режим TUN` (Tun Mode), `Системный прокси` (System Proxy) или оба, а также включён ли [kill switch](@/advanced/kill_switch.ru.md). |
| Тип профиля | Столбец `Тип` (Type), например `VLESS (Xray)`. Не сама ссылка. |

Для проблем с маршрутизацией используйте шаблон `Routing Issue` и добавьте свой профиль маршрутизации: в `Настройки` (Settings) → `Настройки маршрутизации` (Routing Settings) → `Маршрутизация` (Route) выберите профиль и нажмите `Экспорт` (Export), чтобы скопировать ссылку `throne://route/…`. Сначала проверьте, нет ли в ней личных доменов и адресов.

Если разработчик попросит вашу конфигурацию, щёлкните профиль правой кнопкой мыши → `Поделиться` (Share) → `Экспортировать конфиг` (Export config) (только в расширенном режиме) и скопируйте вкладку `sing-box` или, если попросят, вкладку `Xray`. Сначала замените пароли, UUID, ключи и адреса серверов на `xxxx`.

Для headless Throne см. также [Что указать в отчёте об ошибке](@/headless/troubleshooting.ru.md#reporting).
