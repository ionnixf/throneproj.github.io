## Чем Throne отличается от Nekoray? {#nekoray}

Throne — продолжение Nekoray, который больше не развивается. Throne работает на собственном ядре ThroneCore на основе sing-box, которое использует Xray только для профилей Xray, и в нём появились такие функции, как автовыбор (Auto Selector), Cloudflare WARP, профили OpenVPN и OpenConnect, резервное копирование и приложение для Android. Throne не умеет читать конфигурацию Nekoray; см. [Переход с Nekoray / NekoBox](@/help/migrating.ru.md).

## В программе нет пункта меню или параметра из этой документации. Где он? {#missing-option}

Новая установка запускается в простом режиме, который скрывает дополнительные пункты. Нажмите `Ctrl+K` и введите название параметра, чтобы найти и открыть его, или переключитесь в расширенный режим в `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Интерфейс` (Style) → `Интерфейс` (Interface). Если пункта всё равно нет, возможно, ваша версия старше той, что описана в документации, или этот пункт есть только в других системах. См. [Простой и расширенный режим](@/get_started/configuration.ru.md#interface-mode).

## Есть ли портативный режим? {#portable}

Да. ZIP-сборки для Windows и Linux хранят все данные в папке `config` рядом с программой, поэтому всю папку `Throne` можно скопировать в другое место или на другой компьютер. Пакеты, установочный скрипт для Linux и приложение для macOS хранят данные в вашем профиле пользователя. См. [Командная строка, файлы и логи](@/reference/files.ru.md#data-folder).

## Можно ли пользоваться Throne на Android и перенести туда свою конфигурацию? {#android}

Да. [Throne для Android](@/android/_index.ru.md) использует то же ядро и тот же формат резервных копий. Создайте резервную копию в `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Резервное копирование и восстановление` (Backup and Restore), скопируйте файл `.thrbackup` на телефон и восстановите его в приложении; в обратную сторону это тоже работает. См. [Резервное копирование, обновление и перенос](@/guides/backup.ru.md#desktop-android).

## Может ли Throne работать на сервере без окна? {#headless}

Да. `Throne --headless` работает на сервере, роутере или в контейнере; пакеты для Linux содержат для него службу systemd, а ещё есть образ Docker. Управляют им с помощью `thronectl` или его [веб-интерфейса](@/headless/web.ru.md). См. [Headless Throne](@/headless/_index.ru.md).

## Можно ли управлять Throne из скрипта или со Stream Deck? {#scripts}

Да. Включите `Настройки` (Settings) → `Настройки интеграции` (Integration Settings) → `Throne API` (только в расширенном режиме) и используйте `thronectl`: например, `thronectl toggle` на клавише Stream Deck подключает и отключает Throne. Без API из любого приложения работают [глобальные горячие клавиши](@/reference/shortcuts.ru.md#global-hotkeys) `Запустить/остановить профиль` (Start/Stop Profile) и `Вкл./выкл. режим TUN` (Toggle Tun Mode). См. [Throne API и thronectl](@/advanced/api.ru.md).

## Почему антивирус считает Throne опасным? {#antivirus}

Это ложные срабатывания на обычные функции: программа обновления заменяет файлы программы, в Windows Throne записывает ключи реестра, а режим TUN меняет сетевые настройки ([#1127](https://github.com/throneproj/Throne/issues/1127)). Скачивайте Throne только с официальной [страницы загрузок](@/downloads.ru.md) и добавьте папку Throne в исключения антивируса. Сетевая защита антивируса также может блокировать режим TUN без каких-либо сообщений; см. [Устранение неполадок](@/help/troubleshooting.ru.md#tun).

## Отправляется ли кому-нибудь идентификатор моего устройства (HWID)? {#hwid}

Только если вы это включите. Параметр `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Подписка` (Subscription) → `Включить отправку HWID, модели устройства и версии ОС при обновлении подписки` (Enable sending HWID, device model, and OS version when updating subscription) по умолчанию выключен; когда он включён, эти значения отправляются только с запросами подписок. Каждая группа может переопределить его с помощью `Отправлять HWID` (Send HWID) в своих настройках подписки `Доп. настройки` (Advanced) (оба параметра — только в расширенном режиме). Некоторые провайдеры этого требуют. См. [Конфиденциальность и сетевые запросы](@/reference/privacy.ru.md#hwid).

## Есть ли kill switch? {#kill-switch}

Да: `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Безопасность` (Security) → `Kill switch` (Kill Switch). Пока Throne работает, он блокирует весь трафик, который идёт не через Throne, даже когда ни один профиль не запущен; ему нужны те же права, что и режиму TUN. См. [Kill Switch](@/advanced/kill_switch.ru.md). На Android назначьте Throne постоянной VPN (always-on VPN) и включите системный параметр, который блокирует подключения без VPN; см. [Разрешения и работа в фоне](@/android/permissions.ru.md#always-on).

## Почему режиму TUN нужны права администратора или root? {#tun-admin}

Режим TUN создаёт виртуальный сетевой адаптер, который перехватывает трафик системы, а это разрешено только администраторам. Режиму системного прокси особые права не нужны. В Windows Throne перезапускается от имени администратора и с тех пор всегда запускается так, если не включить `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Безопасность` (Security) → `Всегда запускать Throne от имени обычного пользователя` (Always Start as Standard User) (только в расширенном режиме). В Linux и macOS права root получает только ядро, а не окно. См. [Режим TUN](@/guides/tun_mode.ru.md#privileges).

## Действительно ли в Linux нужен бит SUID? {#linux-suid}

Ядру для режима TUN нужны права root, а окно Throne работает от имени вашего обычного пользователя, поэтому не запускайте Throne через `sudo`. По умолчанию Throne с помощью `pkexec` (polkit) делает владельцем `ThroneCore` пользователя root и устанавливает бит SUID. Вместо этого можно выдать ядру пять возможностей (capabilities) с помощью `setcap`. Чтобы Throne перестал запрашивать права, включите `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Безопасность` (Security) → `Не запрашивать повышение прав` (Disable Privilege request) (только в расширенном режиме). См. [Режим TUN](@/guides/tun_mode.ru.md#privileges).

## Почему после принудительного закрытия Throne перестал работать интернет? {#force-quit}

Когда включён `Системный прокси` (System Proxy), Throne, пока запущен профиль, направляет системную настройку прокси на свой локальный порт и убирает её, когда профиль останавливается или вы выходите из Throne. Если процесс Throne завершён принудительно, настройка остаётся, и приложения пытаются использовать прокси, который уже не работает. Чтобы это исправить, запустите Throne, запустите любой профиль с отмеченным `Системный прокси`, затем остановите его или выйдите через `Программа` (Program) → `Выход` (Exit). Вы также можете отключить прокси в сетевых настройках системы.

## Почему системный прокси отключается, когда профиль останавливается? {#system-proxy-off}

Throne устанавливает системный прокси только на то время, пока запущен профиль, чтобы приложения никогда не пытались использовать неработающий прокси. Флажок `Системный прокси` (System Proxy) остаётся отмеченным, и Throne снова устанавливает прокси, когда вы запускаете профиль. См. [Системный прокси, TUN и доступ из локальной сети](@/guides/proxy_modes.ru.md#system-proxy).

## Почему тест на утечку DNS показывает DNS-сервер моего интернет-провайдера? {#dns-leak-test}

Часто это ожидаемо. Домены, подпадающие под ваши правила `direct`, разрешаются через `DNS для прямых запросов` (Direct DNS) — обычно это DNS интернет-провайдера, а в режиме системного прокси приложения и браузеры могут разрешать имена без Throne. В разделе [Тесты на утечку DNS](@/guides/dns.ru.md#leak-tests) перечислены ожидаемые результаты и что менять.

## Почему после обновления подписки мой профиль остановился или продолжил работать? {#profile-after-update}

Обновление останавливает запущенный профиль, только если вы это разрешили. Если обновление удалило бы запущенный профиль, Throne его оставляет, если не включено `Настройки` (Settings) → `Основные настройки` (Basic Settings) → `Подписка` (Subscription) → `Разрешить остановку активного профиля` (Allow stopping the active profile) (только в расширенном режиме). Если провайдер изменил только настройки профиля, Throne сохраняет их без переподключения; чтобы применить их, запустите профиль снова. См. [Подписки и группы](@/guides/subscriptions.ru.md#running-profile).

## Почему в подписке появляются профили `Custom`? {#custom-config-import}

Throne разбивает JSON-конфигурации sing-box и Xray на профили — по одному на сервер, но оставляет целыми полные конфигурации Xray (`Custom Xray Config`), outbound Xray с протоколом, отличным от VLESS (`Custom Xray … Outbound`), и отдельные outbound sing-box (`Custom … Outbound`). Групповые outbound, например `selector` и `urltest`, не импортируются; вместо них используйте [автовыбор](@/guides/testing.ru.md#auto-selector). См. [Протоколы и форматы импорта](@/reference/protocols.ru.md#import-formats).

## Откуда берутся скачиваемые профили маршрутизации? {#route-profiles-source}

Из репозитория [throneproj/routeprofiles](https://github.com/throneproj/routeprofiles), где также хранится список встроенных наборов правил `geoip-…` и `geosite-…`. Сами файлы наборов правил берутся из таких проектов, как MetaCubeX meta-rules-dat, Chocolate4U Iran-sing-box-rules и runetfreedom russia-v2ray-rules-dat. См. [Маршрутизация](@/guides/routing.ru.md#download-profiles).

## Чем отличаются пакеты `.deb`? {#deb-variants}

Обычный `.deb` содержит собственную копию Qt и работает в Debian 10, Ubuntu 20.04 или новее. Пакет `-system-qt.deb` использует Qt 6 вашего дистрибутива, и ему нужен Debian 12, Ubuntu 22.04 или новее. Начните с обычного пакета и используйте `system-qt`, если он не запускается, например на процессорах без SSE4.2 ([#845](https://github.com/throneproj/Throne/issues/845)). Такая же пара есть для arm64 и в виде `.rpm`; см. [Установка](@/get_started/installation.ru.md#linux).

## Какие пакеты официальные? {#third-party-packages}

Официальные — это файлы на [странице релизов GitHub](https://github.com/throneproj/Throne/releases), установочный скрипт для Linux, APT- и RPM-репозитории, пакет `throne` в AUR и Homebrew cask `throneproj/tap/throne`. Пакеты WinGet, Scoop и Nix, а также другие пакеты AUR, например `throne-bin`, создаёт сообщество, и разработчики их не поддерживают ([#1182](https://github.com/throneproj/Throne/issues/1182), [#1622](https://github.com/throneproj/Throne/issues/1622)). Если проблема возникает только с таким пакетом, сообщите о ней его сопровождающему. См. [Менеджеры пакетов](@/get_started/installation.ru.md#package-managers).

## Какая сборка нужна для Windows 7, старой macOS, старого Linux или старого процессора? {#old-systems}

- **Windows 7 SP1 и Windows 8:** `windowslegacy64.zip` (64-битная система), `windows32.zip` (32-битная) или универсальный установщик, который сам выберет legacy-сборку.
- **Mac с процессором Intel и macOS с 10.15 по 14.3:** `macoslegacy-amd64.zip`. Более старые версии macOS не поддерживаются.
- **Старые дистрибутивы Linux** (Debian 10, Ubuntu 20.04, RHEL 8): ZIP-файл, установочный скрипт или обычные пакеты. Пакетам `-system-qt` и репозиториям нужен Debian 12, Ubuntu 22.04, RHEL 9 или новее.
- **Процессоры без SSE4.2:** `windowslegacy64.zip` в Windows, пакет `-system-qt` в Linux ([#845](https://github.com/throneproj/Throne/issues/845)).

В таблице на [странице загрузок](@/downloads.ru.md) указаны минимальные требования к системе для каждого файла.
